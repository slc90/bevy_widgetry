# 增加文件窗口示例

## 目标

改造 `gallery` 中的 Window 页面，使其按三个独立区块展示：

1. `Independent Window`
2. `MessageBox`
3. `File Dialog`

前两个区块继续展示项目自身已有控件；第三个区块仅用于展示 Windows 原生文件对话框，使用 `rfd`。

本次只考虑 Windows，不做跨平台适配。

---

## 约束

- 使用 Bevy `0.19.1`。
- Gallery 现有 UI 继续使用 BSN。
- 不引入旧式 `mod.rs` 布局。
- 不把 File Dialog 封装成 `bevy_widgetry` 控件。
- 不修改 `crates/bevy_widgetry` 的公共 API 来迁就此示例。
- 文件对话框不能阻塞 Bevy 主线程。
- File Dialog 应以 Gallery 主窗口为 parent，使其表现为相对于主窗口的模态窗口。
- 每个 File Dialog 示例都拥有自己独立的结果 `Text`。
- 不增加页面级 `Resource` 保存 File Dialog 状态。
- 只读取/修改本任务需要的 Gallery 代码，避免顺手重构无关模块。

## Window 页面布局

三个区块纵向排列。

每个区块结构统一为：

```text
────────────────────────────────
标题 Text
内容
```

注意：

- 标题使用普通 `Text`
- 横线在标题上方
- 横线不是标题下划线
- 标题不是 Button
- 不创建 `section()` 之类的额外 UI DSL 封装
- 继续直接使用 BSN

建议用区块根节点的 top border 表示横线，而不是单独创建一个 1px Node：

```rust
Node {
    width: percent(100),
    border: UiRect::top(px(1)),
    padding: UiRect::top(px(12)),
    flex_direction: FlexDirection::Column,
    row_gap: px(8),
    ...
}
```

横线颜色使用当前主题的：

```rust
ThemeMode::colors().window_border
```

### File Dialog 排版要求

第一行放四个打开/选择类操作：

1. `Open File`
2. `Open Files`
3. `Select Folder`
4. `Open Image`

第二行单独放：

5. `Save File`

每一个按钮下面必须直接有一个与自己对应的结果 `Text`。

可以把每个按钮 + Result Text 看成一个纵向小单元：

```text
[ Open File ]
Result: ...
```

四个小单元再横向排列。

## File Dialog 行为

只使用异步 File Dialog。

不要在 Bevy observer / system 中直接调用同步的：

```rust
rfd::FileDialog::pick_file()
```

因为同步 API 会阻塞调用线程；Gallery 不应因此停止 Bevy 主循环。

使用：

```rust
rfd::AsyncFileDialog
```

### 必须支持的示例

#### Open File

```rust
AsyncFileDialog::new()
    .set_title("Open File")
    .pick_file()
    .await
```

Result 示例：

```text
Result: C:\foo\bar.txt
```

取消：

```text
Result: Cancelled
```

---

#### Open Files

```rust
AsyncFileDialog::new()
    .set_title("Open Files")
    .pick_files()
    .await
```

结果可以显示：

- 选中的完整路径列表；或
- 在空间不足时至少显示数量

优先完整路径列表，因为这是 Gallery 示例。

---

#### Select Folder

```rust
AsyncFileDialog::new()
    .set_title("Select Folder")
    .pick_folder()
    .await
```

显示选择的文件夹路径。

---

#### Open Image

使用文件过滤器：

```rust
AsyncFileDialog::new()
    .set_title("Open Image")
    .add_filter("Images", &["png", "jpg", "jpeg", "bmp", "webp"])
    .pick_file()
    .await
```

显示选择的图片路径。

---

#### Save File

单独一行：

```rust
AsyncFileDialog::new()
    .set_title("Save File")
    .set_file_name("output.txt")
    .save_file()
    .await
```

显示最终路径。

---

## parent / 模态关系

File Dialog 应绑定 Gallery 的 Bevy 主窗口作为 parent。

目标行为：

```text
文件窗口打开
    ↓
Gallery 主窗口暂时不可交互
    ↓
Bevy 主循环继续运行
    ↓
选择 / 取消后 Future 完成
    ↓
更新对应 Result Text
```

不要把“模态”和“阻塞”混为一谈。

### 获取主窗口

Gallery 当前已经使用：

```rust
PrimaryWindow
```

File Dialog handler 应继续以主窗口 Entity 为目标。

在 Bevy 0.19 中，若使用 `bevy::winit::WINIT_WINDOWS` 获取底层 winit Window：

- 相关访问必须在主线程执行
- observer/system 可加入 `NonSendMarker` 约束其运行在主线程
- 在主线程中调用 `set_parent(...)`
- `set_parent(...)` 完成后再把构造好的 `AsyncFileDialog` 移入异步 task

实现时请以当前 Bevy 0.19.1 / rfd 版本的实际 API 为准，不要套旧版 `WinitWindows` 示例。

项目 workspace 当前禁止 unsafe：

```toml
[workspace.lints.rust]
unsafe_code = "forbid"
```

因此不要为了 raw window handle 引入自写 unsafe。

## 异步结果状态

不要增加这样的页面 Resource：

```rust
struct WindowPageState {
    open_file_result: ...,
    open_files_result: ...,
    ...
}
```

每个结果已经对应一个 `Text`，不需要再保存一份页面状态。

允许定义一个非常薄的私有 Component，让 Result Text 自己持有正在等待的 task，例如：

```rust
#[derive(Component, Default)]
struct FileDialogResult {
    task: Option<Task<String>>,
}
```

语义：

```text
Result Text Entity
├─ Text
└─ FileDialogResult
   └─ Option<Task<String>>
```

点击按钮时：

1. 找到该按钮对应的 Result Text
2. 将 Text 改成：

```text
Result: Waiting...
```

3. 创建异步 task
4. 将 task 放进 Result Text 上的 `FileDialogResult`

---

## Result Text 与按钮关联

不需要定义页面级 ID 表或 Resource。

建议每个 File Dialog 示例结构为：

```text
Demo Item Node
├─ Button
└─ Result Text + FileDialogResult
```

按钮触发时通过 ECS 层级找到同一 Demo Item 下的 Result Text。

避免硬编码 Entity。

如果 BSN 中有更直接、现有项目已经使用的实体绑定方式，也可以采用，但不要为了这个示例建立复杂状态管理层。

---

## task 轮询

增加一个统一 Update system，例如：

```rust
fn poll_file_dialog_results(
    mut results: Query<(&mut Text, &mut FileDialogResult)>,
) {
    // 非阻塞 poll
}
```

要求：

- 每帧只检查 task 是否 ready
- 未完成时立即返回
- 完成后：
  - 更新 Text
  - 清空 `task`
- 不调用 `block_on`
- 不阻塞 Bevy 主线程

可以使用 Bevy 0.19 当前提供的 task/future 非阻塞检查 API。

---

## File Dialog 重复点击

建议做最小保护：

如果对应 Result Text 上已经存在未完成 task，则本次点击直接忽略。

即：

```rust
if result.task.is_some() {
    return;
}
```

避免同一个示例连续弹出多个原生文件窗口。

不同示例是否允许同时打开多个 dialog，可以保持自然行为，不需要额外做全局锁。

## Theme

Window 页面普通文字继续跟随 Gallery 当前主题。

三个区块的 top border 也必须跟随主题切换。

建议父页面维护：

```rust
#[derive(Component)]
struct WindowDemo;

#[derive(Component)]
struct WindowDemoSection;
```

父根节点负责：

```rust
Propagate<ForegroundColor>
```

区块根节点负责：

```rust
BorderColor
```

在 `ThemeChanged` observer 中统一刷新。

不要让 File Dialog 自己引入额外主题状态。

原生 Windows File Dialog 的外观交给系统。

## Cargo 依赖

`rfd` 只应作为 Gallery 的依赖，不作为 `bevy_widgetry` 控件库依赖。

推荐在 workspace dependency 中声明版本，然后由 gallery 使用：

### 根 `Cargo.toml`

```toml
[workspace.dependencies]
rfd = { version = "0.17.2", default-features = false }
```

### `gallery/Cargo.toml`

```toml
[dependencies]
rfd.workspace = true
```

如果当前 rfd Windows backend 对 feature 有额外要求，请以该版本 Cargo metadata 为准，只启用 Windows 所需 feature。

不要为了 Linux/macOS 支持额外启用 GTK / portal 等依赖。

## `WindowDemoPlugin`

最终仍由一个 Window 页面 plugin 对外提供。

大致职责：

```rust
impl Plugin for WindowDemoPlugin {
    fn build(&self, app: &mut App) {
        app
            .add_plugins(MessageBoxPlugin)
            .add_observer(refresh_window_demo_theme)
            .add_observer(message_box::on_message_box_result)
            .add_systems(Update, file_dialog::poll_results);
    }
}
```

也可以让 `file_dialog.rs` 自己提供一个私有：

```rust
pub(super) struct FileDialogDemoPlugin;
```

然后：

```rust
.add_plugins(file_dialog::FileDialogDemoPlugin)
```

两种都可以。

倾向后者，因为 file dialog 的 runtime 行为应该收在它自己的模块里。
