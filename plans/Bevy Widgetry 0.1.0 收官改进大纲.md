# Bevy Widgetry 0.1.0 收官改进大纲

## 一、代码与功能整理

### 01. 全仓库冗余、遗留及无效内容审查

全面检查源码、依赖、配置、测试、文档、资源和辅助脚本，识别冗余、重复、过时及无效内容，按实际价值决定是否清理或整合。

### 02. 统一控件初始化与默认配置约定

回顾各控件的初始化方式、Props 默认值、必填参数、空状态及错误行为，检查是否存在不必要的不一致。

### 03. 统一 Widgetry 错误体系

统一错误语义、分类、构造和传播约定。对外仍然使用 BevyError，不建立独立的外部错误体系。

### 04. 全仓库日志审查与日志规范完善

回顾各 crate 的日志记录情况，检查日志等级、上下文、重复记录及诊断缺口，按需补充日志并改进 `rules/logging.md`。

### 05. 细粒度 Cargo Feature 与按需编译

检查是否可以在 crate 内进一步按功能和资源控制编译范围，优先考虑 Kamuri Cursor 等相对独立、具有明显资源成本的功能。

### 06. FileDialog UI 重新设计

改善 FileDialog 的布局、视觉风格、图标、间距及交互区域组织，原则上不改动已经完成的业务功能。

### ~~07. Gallery 用户数据存储位置调整~~

~~回顾配置、日志及其他持久化数据的存储方式，确保 Gallery 在独立安装后仍能合理、可靠地管理这些数据。~~

## 二、测试与构建验证

### 08. Cargo Feature 组合与独立编译验证

检查默认、全部关闭、全部开启及代表性 Feature 组合的编译正确性，特别关注独立项目使用时的实际依赖关系。

### 09. 全仓测试审查与测试文档整理

回顾所有 crate 的单元测试与集成测试，检查测试质量、重复测试及重要行为的覆盖缺口。

为各 crate 分别整理 Markdown 测试说明，同时回顾并改进现有 `tests/COVERAGE.md`。

## 三、文档与工程规范

### 10. docs/ 文档体系整体重构

重新组织和撰写当前文档，区分功能说明与内部设计说明。

重点补全当前仓库的整体架构、跨模块机制及各模块设计，形成能够独立理解当前实现的设计文档体系。

历史 `plans/` 保留为设计背景，不直接作为当前实现事实。

### ~~11. Gallery BRP Agent 操作手册~~

~~编写面向 Codex 等 Agent 的 Gallery 操作说明，介绍如何利用 BRP 连接、定位、操作和验证 Gallery 中的 UI。~~

### 12. AGENTS.md 与 rules/ 整体回顾和改进

检查现有规则是否存在冲突、重复、过时或不合理的约束，并结合前面的改进同步调整。

重点确立 **「整体 → 局部 → 整体」** 的开发原则，要求 Agent 在修改前理解相关设计、修改时聚焦局部、修改后检查整体影响。

## 四、工具与工程经验沉淀

### 13. Animated Cursor Skill 独立化与完善

回顾现有 `animated-cursor-authoring` Skill，改进通用性、使用流程和工具验证，将其从 Widgetry 仓库移出，整理为可独立安装到 ChatGPT 的 Skill 包。

### 14. 通用 Rust 仓库初始化模板

以前述工作完成后的仓库为参考，使用 `cargo-generate` 制作独立的通用 Rust 项目模板。

重点沉淀 Workspace 组织、工程规范、Agent 协作、文档结构和辅助工具，不继承 Widgetry 特有的技术约束。

## 五、最终验收与发布

### 15. 独立使用验收与 Git Tag 0.1.0

完成以下最终验收：

- 在新的独立 Rust 项目中，通过 Git 依赖使用 Widgetry。
- 验证 Gallery 能否通过 `cargo install --git` 安装并独立运行。
- 完成必要的全仓构建、测试及运行验证。

**全部改进和验收完成后，最后创建并推送 Git Tag `0.1.0`。**
