# 规范化文件日志的事件源码位置

文件日志需要保留“哪段代码记录了这条消息”的信息，却不需要知道源码是在谁的用户目录、Cargo 缓存目录或临时安装目录中编译的。当前文件层直接启用 `with_file(true)`、`with_line_number(true)`，因此第三方依赖的 `Metadata::file()` 可能直接显示为构建机器上的绝对路径。将这一层改成**使用安全的源码标识渲染 Metadata**，不改变调用方产生日志的方式。

目标是让普通 DEBUG/INFO/WARN/ERROR 事件具备稳定、可检索的模块／文件／行号位置，同时不输出事件元数据中的原始绝对路径。本增量只处理普通事件的来源元数据；`ErrorOrigin`、Backtrace 以及日志字段中另行携带的异常文本由下一份方案处理。

## 文件日志的正常输出

`tracing` 提供的 `Metadata` 同时包含 `module_path()`、`target()`、`file()` 与 `line()`。`target` 可能被业务宏显式改写（例如统一使用 `widget_gallery`），因此不能把 `target` 当成唯一的调用点位置。源码标识优先由 `module_path` 和经过裁剪的文件名组成，并保留行号。模块名缺失时才回退到 `target`；文件名或行号缺失时只省略对应信息。

例如，将以下事件位置：

```text
C:\Users\builder\.cargo\registry\src\index.crates.io-xxxx\bevy_app-0.20.0\src\app.rs:528
```

呈现为：

```text
bevy_app::app (app.rs:528)
```

项目内事件也统一采用这套格式，例如：

```text
widget_gallery::gallery (gallery.rs:254)
```

这比把 Windows 绝对路径硬编码成某一个固定前缀更可靠：不同开发者、CI 和 `cargo install --git` 的临时目录都不影响日志表示。模块名还可以消除多个 crate 都有 `lib.rs`、`mod.rs` 的歧义。

```mermaid
flowchart LR
    E[Tracing Event] --> M[Metadata]
    M --> S[安全位置: module_path + 文件名 + 行号]
    E --> F[原有事件字段]
    S --> O[文件日志事件格式]
    F --> O
    O --> Q[原有后台写入队列]
```

## 格式化职责与接入方式

在 `crates/app_logging/src/logging.rs` 的文件层增加一个专用 `FormatEvent`（可放在内聚的小模块中），通过 `fmt::Layer::event_format(...)` 接入。格式器从事件元数据构造安全来源标识，再委托 `FmtContext`／`FormatFields` 处理原有事件字段及 Span 上下文。它不打印未经处理的 `Metadata::file()`。

路径裁剪函数接受 `&str`，同时识别 `\\`、`/` 两种分隔符，**只提取最后一个文件名组件**；无需知道编译工作目录，也不能通过简单的字符串替换把某个用户主目录写死。来源字符串无法识别时，回退为安全的模块／target 标签或固定的“未知源码”，而不是回退为原始路径。行号来自 `Metadata::line()`，不能通过解析原始路径猜测。

事件格式应继续保留现有的本地时间及毫秒、日志等级、线程名、线程 ID、事件字段与 Span 上下文的有用信息；日志正文和字段值不因为只改来源位置而被删改。现有文件层 DEBUG 及以上、终端 INFO 及以上的过滤策略不变，TRACE 仍关闭。终端层原本不显示源码文件位置，本增量无需改变终端显示策略。

格式化必须在交给 `FileWriter`／`tracing_appender` 队列**之前**完成，不在后台异步线程修改落盘数据；这样不会改变队列容量、非丢失写入、刷新、故障与 Guard 的计数及收尾语义。

## 验证与完成条件

用独立的路径裁剪单元测试覆盖 Windows 盘符路径、Unix 风格路径、反斜杠与正斜杠混用、含空格和中文目录、仅文件名、空字符串等情况。输入是源码元数据；输出不能含盘符根目录、Cargo 缓存或构建用户名。

用 `tracing` 事件的实际格式化测试覆盖第三方默认 target、显式 `target`、缺失 `module_path`／`file`／`line` 的回退行为，并验证事件字段、日志等级、时间、线程信息没有丢失。正常启动 Gallery 后，日志中 Bevy 插件注册位置应从 `.cargo\\registry\\src\\...` 形式变成模块／文件／行号；项目自身的 `gallery`、`crates` 事件也应仍可定位。

实施完成时，文件日志中的事件**来源元数据**不再暴露构建机绝对路径；错误字段与完整回溯会在下一增量统一收口。

## 边界

不修改各控件日志宏、事件生成逻辑、错误生命周期、后台 writer、`Cargo.toml` 的 Release profile 和 Cargo 安装命令。`bevy_widgetry_app_logging` 是宿主可选使用的日志能力；此次改变的是它的默认文件日志展示格式，不应让基础控件库自行安装日志订阅器。

参考：[Tracing Metadata](https://docs.rs/tracing-core/latest/tracing_core/struct.Metadata.html)、[FormatEvent](https://docs.rs/tracing-subscriber/0.3.23/tracing_subscriber/fmt/format/trait.FormatEvent.html)。
