# 公开托盘初始化状态

## 目标

`WidgetryTrayPlugin` 目前已经能够完成托盘图标创建、Windows Shell 注册确认和原生事件桥接，但初始化结果只保存在插件内部的 `TrayOwner` 中。

宿主应用无法直接判断托盘是否已经成功初始化，只能依赖错误日志推测。

为此，向 `bevy_widgetry::tray` 增加公开的 `WidgetryTrayStatus` Resource，让宿主能够通过 ECS 查询托盘初始化状态。

本次只扩展 Widgetry 的公共状态接口，不改变现有托盘创建、菜单、事件桥接和资源释放机制。

## 状态模型

托盘初始化状态分为三个阶段：

```mermaid
stateDiagram-v2
    [*] --> Initializing: WidgetryTrayPlugin::build
    Initializing --> Ready: 原生托盘初始化成功
    Initializing --> Failed: 初始化失败
    Ready --> [*]: 应用退出
    Failed --> [*]: 应用退出
```

公开类型：

`WidgetryTrayStatus` 是一个 Bevy Resource，包含三个状态：

| 状态 | 含义 |
|---|---|
| `Initializing` | 插件已安装，尚未完成原生托盘初始化 |
| `Ready` | 原生托盘图标已经创建，并通过 Windows Shell 注册确认 |
| `Failed` | 原生托盘初始化失败 |

状态只描述启动阶段的初始化结果，不作为持续运行期间的托盘健康监控。

## 初始化过程

### 初始状态

在 `WidgetryTrayPlugin::build` 中插入 `WidgetryTrayStatus::Initializing`。

这样宿主在插件安装完成后，就能通过 Resource 获取初始状态，不需要等待托盘初始化系统执行。

### 成功状态

现有 `initialize` 系统继续负责调用 `initialize_instance`。

只有在以下步骤全部成功后，才将状态切换为 `Ready`：

1. 获取 Winit EventLoop Proxy。
2. 创建原生 RGBA 图标。
3. 创建原生菜单（如果宿主提供了菜单）。
4. 创建 `TrayIcon` 实例。
5. 通过 `set_tooltip` 确认 Windows Shell 注册成功。
6. 建立原生事件桥接及实例路由。
7. 安装菜单交互监听（存在菜单时）。
8. 将完整的 `TrayInstance` 保存到 `TrayOwner`。
9. 提交事件 Inbox。

状态不能仅根据 `TrayIconBuilder::build` 成功就切换为 `Ready`，因为原生图标创建成功不等于已经成功注册到通知区域。

### 失败状态

如果 `initialize_instance` 返回 `TrayFailure`：

- 将状态切换为 `Failed`。
- 保留原始 `TrayFailure`，继续通过现有 Bevy 错误处理机制传播。
- 不创建或保留未完成初始化的 `TrayInstance`。
- 不吞掉错误，也不把错误转换成普通字符串作为唯一信息。

状态只提供宿主需要的初始化结果。具体错误原因仍由现有 Diagnostics 机制负责记录和传播。

### 构造阶段的错误

`WidgetryTrayPlugin::new` 在插件安装之前就会解码 ICO。

如果 ICO 无效，该函数仍然直接返回 `TrayFailure`，不创建 `WidgetryTrayStatus` Resource。

本次状态接口只覆盖插件安装后的 Startup 初始化过程，不改变构造函数的错误契约。

## 公共 API

在 `crates/tray/src/plugin.rs` 中定义公开状态类型，并在 `crates/tray/src/lib.rs` 中导出：

```rust
#[derive(Resource, Clone, Copy, Debug, Default, PartialEq, Eq)]
pub enum WidgetryTrayStatus {
    #[default]
    Initializing,
    Ready,
    Failed,
}
```

公共使用方式：

```rust
use bevy::prelude::*;
use bevy_widgetry::tray::WidgetryTrayStatus;

fn check_tray(status: Res<WidgetryTrayStatus>) {
    match *status {
        WidgetryTrayStatus::Initializing => {
            // 保持主窗口正常显示
        }
        WidgetryTrayStatus::Ready => {
            // 托盘已经可用
        }
        WidgetryTrayStatus::Failed => {
            // 保持主窗口正常显示
        }
    }
}
```

不增加额外的状态变化消息。宿主可以通过 `Res` 读取状态，并使用 Bevy Resource 的变化检测机制观察状态更新。

### 状态语义边界

`Ready` 表示初始化时已经完成原生图标创建和 Shell 注册确认，不代表托盘在整个运行期间永远不会发生故障。

初始化完成后的其他错误，例如：

- 托盘点击事件队列溢出。
- Winit 唤醒失败。
- 原生菜单同步失败。
- 菜单交互监听期间发生错误。

继续使用现有 `TrayFailure` 和 Diagnostics 传播，不修改初始化状态。

`Failed` 同样是启动初始化结果，不设计运行时自动重试或状态恢复机制。

## 需要修改的模块

### `crates/tray`

- `src/plugin.rs`
  - 定义 `WidgetryTrayStatus`。
  - 在插件安装时初始化状态 Resource。
  - 在 `initialize` 中根据完整初始化结果更新状态。
  - 保持现有 `initialize_instance` 的资源所有权和错误传播方式。

- `src/lib.rs`
  - 导出 `WidgetryTrayStatus`，使底层 Crate 的使用者能够访问。

### Facade

`crates/bevy_widgetry/src/lib.rs` 中的 `tray` 模块已经使用：

`pub use bevy_widgetry_tray::*`

因此新增的公开类型会自动通过 `bevy_widgetry::tray` 暴露，不需要增加第二套导出机制。

## 验证要求

在现有 `crates/tray/src/plugin.rs` 测试模块中补充状态覆盖：

1. 插件安装后，状态为 `Initializing`。
2. ICO 解码失败仍由 `WidgetryTrayPlugin::new` 返回错误，不产生初始化状态 Resource。
3. 缺少 Winit EventLoop 时，初始化状态变为 `Failed`。
4. 初始化失败仍然将原始诊断交给宿主错误处理器，不因更新状态而丢失来源身份和错误上下文。
5. 完整原生初始化成功后，状态变为 `Ready`。
6. `Ready` 不因后续菜单同步错误而被误改为 `Failed`。

成功初始化的测试沿用现有 Windows 原生托盘测试方式，覆盖完整初始化路径，而不是仅测试状态枚举赋值。

所有新增代码继续遵循 Workspace 和 `crates/tray` 的现有 Lint 约束：

- 不新增不必要的 `unsafe`。
- 不使用被禁止的 `unwrap`、`expect`、`panic` 等方式处理失败。
- 不引入新的第三方依赖。
- 不安装新的全局错误处理器。
- 不改变原有错误严重级别及 Diagnostics 传播行为。

## 范围边界

- 只修改 `bevy_widgetry` 仓库。
- 不修改 Agentelier 或其他宿主应用。
- 不修改 `WidgetryTrayPlugin` 的原生托盘实现。
- 不增加托盘初始化重试、自动恢复或运行时健康监控。
- 不增加新的菜单行为、窗口管理或退出逻辑。
- 不改变 `WidgetryTrayClick`、`WidgetryTrayMenuClick` 的消息契约。
- 不改变现有托盘资源在 `AppExit` 时的释放机制。

最终交付是一项独立的小型公共 API 增量：宿主能够可靠查询托盘是否完成初始化，而 Widgetry 仍然只负责托盘本身及其初始化结果的公开。
