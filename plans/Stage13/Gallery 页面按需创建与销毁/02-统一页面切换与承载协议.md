# 02｜建立统一的页面切换、挂载和退出协议

## 目标

将 Gallery 导航从切换隐藏节点改为 State 驱动，并确定所有页面共享的 BSN 容器和资源释放契约。

## 范围

`gallery/src/gallery.rs` 的导航与 `page(...)` 容器、`gallery/src/color_showcase.rs` 及 `color_showcase/catalog.rs` 的状态枚举适配、共用生命周期约定。只建协议，不提前替各演示页创建 Model。

## 预期产出

每次只存在一个 PageHost 页面根；状态进入时可以以独占 World 可靠挂载页面，退出时按确定顺序释放；颜色区及 benchmark 页面布局保持原行为。

## 与前后方案的关系

依赖第 01 份提供的状态与 PageHost。此后每一个页面方案都按本协议接入，复用公共挂载/清理边界。

## 方案正文

### 导航只提交 State，不再操作全部 Node

Sidebar 的 `GalleryNavButton(GalleryPage)`、`on<Activate>` 和 Name 保留，但 `on_nav_button_activated` 不再遍历 `GalleryPageContent` 修改 `Node.display`，改为 `NextState<GalleryPage>::set_if_different(nav.0)`。点击当前页面为无操作，不重复初始化、重置或销毁；真正从该页退出再回来才重置。`GalleryPage::Initializing` 仅服务启动，永不在 Sidebar 提供入口。

### 统一 BSN 页面外壳

从 `gallery::scene(...)` 中移走对 11 个页面的 eager BSN 组合，只保留 Sidebar 和 `PageHost`。原 `page(target, content)` 的视觉/结构行为继续作为**按需生成一个页面**的公共封装：页面顶层 `GalleryPageContent(target)`、100% 尺寸、padding、竖向布局；普通模式为 `@color_showcase::scene(target)` + `WidgetryScrollArea` + `GalleryDemoContent` + 独立的示例 SceneList。`constrain_demo_content` 仍在 `PostUpdate.before(UiSystems::Layout)` 根据 `Added<GalleryDemoContent>` 修正宽度，不能因旧页面移除而停用。

保留现有特殊条件：当 `GALLERY_WAVEFORM_BENCH_OUTPUT` **或** `GALLERY_FILE_DIALOG_BENCH_OUTPUT` 存在时，原 `page()` 绕过颜色目录及包装 ScrollArea，直接使用示例内容，避免改变基准测试的布局/可见尺寸。这些条件不应被新抽象无意删除。页面 BSN 较深处原有 `Box<dyn SceneList>` 类型擦除，是为避免 Windows 主线程展开巨大嵌套 BSN 时 stack 用尽；按需重组后仍保持必要的 SceneList 类型擦除。

根据 `GalleryPage` 增加 `Initializing` 变体的事实，补齐 `color_showcase::examples()` 和 `catalog::rows()` 的穷尽匹配。`Initializing` 不生成可见颜色示例，不能使用 `unreachable!` 等项目禁止的 panic 路径。`ColorShowcase::Showcase`、展开状态和临时 content 都在当前页面实体子树内；切走后销毁，重进重新折叠。按需展开 ListView/Tree/Table/ComboBox/Waveform 示例时才读取各页 Resource。`WidgetryThemeChanged` Observer 是全局注册，回调使用实体存在性校验，需确认不会将已退出页面的刷新任务重新构建为孤儿实体。

### 页面所有权及独占 World 约定

每个页面的插件在 `Plugin::build()` 中**只注册**对应控件类型/renderer、Observer 与 Schedule System，所有注册只发生一次。页面私有 Model/Root/Generator/Resource 的实际创建放入 `OnEnter(GalleryPage::X)`；页面状态数据放在页面专属 Resource 中，控件自身 selection、Text、DemoStatus 等实例态继续通过 UI Component 保存。普通 Update/PostUpdate/Last 系统由 `in_state(GalleryPage::X)` 控制；Observer 不一定能 `run_if`，读取已移除的页面 Resource 时须使用 Optional Resource/事件源校验，或明确保证不会触发。

有页面自身数据的页面，`OnEnter` 使用一个同步的 `&mut World` 独占 System：先创建实际 Model/其他数据，再将**页面拥有的 Entity ID**写入专属 Resource，最后按需构造页面 BSN Scene 并 `ChildOf(PageHost)` 挂载，给页面根标注 `GalleryPageContent(X)`。`OnExit` 也使用一个独占 System，**先同步 `World::despawn()` 页面根及 UI 子树，后销毁本页拥有的数据源实体，最后移除页面 Resource**。不能把旧建议中的 `DespawnOnExit` 当作严格排序保证；其清理与 `OnExit` 位于不同调度单元，默认没有规定谁先完成。页根可以通过唯一 `GalleryPageContent(X)` 确认，或由页面 Resource 保存 root Entity；不要因此建跨页页面缓存。

`remove_resource` 仅删除 Resource及其中保存的 Entity ID，不会销毁被引用的 ECS 实体；`World::despawn(entity)` 才会移除该实体及组件。外部提供的数据源只解除当前页面的引用，**绝不 `despawn` 外部拥有的真实数据实体**。页面清理只能依据明确的所有权记录，不能遍历所有可见 Widget 或所有同类型 Model 一概删除。应用级 Header/theme Model 和独立 native Window 均不属于页面私有数据。

页面 BSN 构建若失败，错误必须按原项目 `Result/BevyError` 流程报告，立即回收本次已创建但尚未挂在 UI 子树的页面自有数据，避免加载失败时留下半套 Model；不额外设计自动重试、静默 fallback 或通用页面缓存。`crates/core/src/scene.rs` 已提供在 World 中同步 `spawn_scene` 及失败时处理部分 BSN reservation 的能力，应复用现有帮助函数，而不是修改 crate 内实现。`StateTransition` 完成后才运行当前页更新 System，不应有上一个页面的数据参与当前帧更新。

### 退出期间的其他直接依赖

ComboBox Popup 位于 ComboBox 控件的 Children/ChildOf 子树，会跟随 UI 根销毁；Tooltip 的应用级 `TooltipState` 和移除锚点时的清理 Observer 继续由对应 Widget 插件持有，不能作为页面 Resource 删除。导航前旧 UI 的焦点、Pointer/hover、弹层和 BSN deferred commands 不得引用死实体；这些属于回归验证条件，发现实际残留时只修正 Gallery 本次生命周期边界，不顺手重构 Widget 库。
