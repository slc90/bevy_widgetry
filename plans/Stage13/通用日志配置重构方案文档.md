# 通用应用日志配置 crate 重构方案

## 目标

把当前 `gallery/src/logging.rs` 中可复用的应用日志配置下沉到独立 crate。

新 crate 不取代现有 `bevy_widgetry_log`，也不自行封装成 Bevy Plugin。

职责划分：

- `bevy_widgetry_log`
  - 保持现状。
  - 只负责 `widgetry_info!`、`widgetry_warn!`、`widgetry_error!` 等 Widgetry 内部日志宏和统一 target。
- 新应用日志 crate
  - 负责通用 terminal/file layer。
  - 负责日志文件创建、时间格式、本地时区和 non-blocking writer。
  - 提供 Bevy `LogPlugin` 所需的 layer factory。
  - 不决定应用如何组合 `DefaultPlugins`。
- gallery
  - 决定日志目录。
  - 调用新 crate API。
  - 自己通过 `DefaultPlugins.set(LogPlugin { ... })` 完成最终 Bevy 日志配置。

## 新 crate

新增：

```text
crates/app_logging
```

包名暂定：

```text
bevy_widgetry_app_logging
```

加入 workspace members。

依赖：

```toml
[dependencies]
bevy.workspace = true
tracing-appender.workspace = true
tracing-subscriber.workspace = true
time.workspace = true
```

它不依赖 `bevy_widgetry_log`。

## 公开 API

核心类型：

```rust
pub struct AppLogging {
    // 私有 LogOutput
    // 私有 WorkerGuard
}
```

构造：

```rust
impl AppLogging {
    pub fn new(path: impl AsRef<Path>) -> Result<Self>;
}
```

`new()` 立即完成所有可能失败的准备工作：

- 获取本地 `UtcOffset`；
- 根据当前时间生成日志文件名；
- `create_dir_all(path)`；
- 创建新的日志文件；
- 创建 `NonBlocking` writer；
- 创建并暂存 `WorkerGuard`。

日志文件命名规则保持当前行为：

```text
yyyy-MM-dd_HH-mm-ss-SSS.log
```

例如：

```text
2026-10-03_16-22-13-427.log
```

## 接入 App

提供：

```rust
pub fn install(self, app: &mut App) -> WorkerGuard;
```

职责仅有：

1. 将内部 `LogOutput` 插入 Bevy `App`；
2. 将 `WorkerGuard` 返回调用方。

`install()` 不再执行 fallible IO，因此无需返回 `Result`。

调用方必须持有返回的 `WorkerGuard`，直到应用结束：

```rust
let _log_guard = logging.install(&mut app);
```

不将 guard 隐藏进全局状态。

## Layer API

公开：

```rust
pub fn terminal_layer(app: &mut App) -> Option<BoxedFmtLayer>;

pub fn file_layer(app: &mut App) -> Option<BoxedLayer>;
```

这两个函数继续供官方 `bevy::log::LogPlugin` 使用。

### terminal_layer

保持现有行为：

- 输出到 `stderr`；
- 使用本地时间；
- 时间精度到毫秒；
- 不显示 target；
- 不显示 source file；
- 不显示 line number。

### file_layer

保持现有行为：

- 写入 non-blocking 日志文件；
- 使用本地时间；
- 时间精度到毫秒；
- 不显示 target；
- 显示 source file；
- 显示 line number；
- 禁用 ANSI。

## 内部类型

以下保持私有：

```rust
struct LogOutput {
    offset: UtcOffset,
    writer: NonBlocking,
}
```

以及：

```rust
fn timer(...)
```

调用方不需要知道 `NonBlocking`、`UtcOffset` 或 timer 的具体实现。

`WorkerGuard` 可以由新 crate 直接 re-export：

```rust
pub use tracing_appender::non_blocking::WorkerGuard;
```

这样 `install()` 的公共接口不要求使用方直接依赖 `tracing-appender`。

## Gallery 调用方式

gallery 负责决定路径。

当前 gallery 的：

```text
GALLERY_STARTUP_BENCH_STATE
```

属于 gallery/benchmark 策略，不进入通用 crate。

路径选择逻辑仍留在 gallery：

```rust
let log_dir = std::env::var_os("GALLERY_STARTUP_BENCH_STATE")
    .map(|state| PathBuf::from(state).join("logs"))
    .unwrap_or_else(|| Path::new(env!("CARGO_MANIFEST_DIR")).join("logs"));
```

随后：

```rust
let logging = AppLogging::new(log_dir)?;

let mut app = App::new();
let _log_guard = logging.install(&mut app);

app.add_plugins(
    DefaultPlugins
        .set(LogPlugin {
            fmt_layer: terminal_layer,
            custom_layer: file_layer,
            ..default()
        })
        .set(WindowPlugin {
            // ...
        })
        .set(RenderPlugin {
            // ...
        }),
);
```

也就是说仍然使用 Bevy 官方 `LogPlugin`。

新 crate 只是提供它的配置和运行资源，不自己重新实现 subscriber，也不要求禁用官方日志 Plugin。

## Gallery 清理

删除：

```text
gallery/src/logging.rs
```

以及：

```rust
mod logging;
```

`gallery/Cargo.toml` 删除直接依赖：

```toml
tracing-appender.workspace = true
tracing-subscriber.workspace = true
time.workspace = true
```

新增：

```toml
bevy_widgetry_app_logging = { path = "../crates/app_logging" }
```

这些 tracing/time workspace dependency 可以继续留在根 `Cargo.toml`，供新 crate 使用。

## 不修改的部分

`crates/log` / `bevy_widgetry_log` 完全不参与此次重构。

其现有语义继续保持：

```text
Widgetry 内部代码
    ↓
widgetry_info!/warn!/error!
    ↓
target = "bevy_widgetry"
    ↓
宿主安装的 Bevy/tracing subscriber
```

而新 crate 负责：

```text
AppLogging
    ↓
terminal_layer / file_layer
    ↓
bevy::log::LogPlugin
    ↓
最终日志输出
```

两者没有直接依赖关系。

## 验证

重构完成后至少确认：

```text
cargo check -p bevy_widgetry_app_logging
cargo check -p widget_gallery
```

运行 gallery 后确认：

- terminal 日志格式与当前一致；
- 指定目录自动创建；
- 每次运行生成新的带时间戳 `.log` 文件；
- 文件日志包含 source file 和 line number；
- Widgetry 的 `target: "bevy_widgetry"` 日志仍正常进入同一 subscriber；
- `GALLERY_STARTUP_BENCH_STATE` 存在时，日志仍写入其 `logs` 子目录；
- `_log_guard` 生命周期覆盖 `app.run()`。

此次重构只迁移和通用化现有日志配置，不增加新的过滤、日志级别、轮转或配置 Builder。
