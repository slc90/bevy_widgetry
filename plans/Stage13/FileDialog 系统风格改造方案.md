# FileDialog 系统风格改造方案

## 1. 改造目标

目前的 FileDialog 有独立窗口、侧栏、路径编辑、搜索、文件列表、排序、过滤和确认操作，但界面更接近简化的文件管理器：导航按钮占用一整行、路径和搜索各占一行、筛选器放在文件列表下方的工具选项区，常用的“文件名／文件类型／打开”没有形成 Windows 文件对话框熟悉的底部操作区域。

这次改造以 **接近 Windows 11 常见“打开／保存”对话框的布局和操作习惯**为目标，同时保留 Widgetry 自绘窗口、主题系统、已有的后台文件读取机制和可复用业务状态。

明确要求：

1. **移除独立文件选择窗口标题栏中的最大化按钮。**
2. **提供直观的文件扩展名过滤**：底部“文件类型”下拉框显示扩展名，切换后实际过滤文件列表。
3. 重组窗口布局，使路径、搜索、文件区域、文件名及确定／取消操作的位置符合系统文件对话框的常见习惯。
4. 保持现有打开单文件、多文件、选择目录、多目录、保存文件等模式的业务能力及结果语义。

不追求像素级复刻 Windows Shell，也不改用操作系统原生文件对话框。

## 2. 基于当前仓库的实现现状

以下是现有实现事实，不属于本次新增能力。

| 功能               | 当前情况                                                                                          | 本次处理                                 |
| ------------------ | ------------------------------------------------------------------------------------------------- | ---------------------------------------- |
| 独立窗口           | `crates/file_dialog/src/window.rs` 组合 Widgetry Window；目前显式 `maximize_visible: true`        | 改为隐藏最大化按钮                       |
| 模式               | `PickFile`、`PickFiles`、`PickDirectory`、`PickDirectories`、`SaveFile`                           | 保持                                     |
| 路径、搜索         | `style.rs` 中为上下两行，均使用编辑框                                                             | 合并到顶部导航区，继续支持编辑路径和搜索 |
| 常用位置、固定目录 | `controls.rs` 中已有侧栏投影                                                                      | 改为更接近系统习惯的侧栏分组及选中样式   |
| 文件列表           | `view.rs` 使用虚拟滚动行，显示图标、名称、大小                                                    | 增加列表列头、类型及可读大小；保留虚拟化 |
| 筛选模型           | `WidgetryFileDialogFilter { id, label, suffixes, default_extension }` 已存在                      | 复用，不重新实现一套筛选状态             |
| 文件过滤           | `snapshot.rs` 的投影已经按 `query.filter.matches()` 筛选文件，目录不受扩展名过滤影响              | 保留语义，重点完善界面、配置和测试       |
| 保存扩展名         | `confirmation.rs` 已支持无后缀时追加 `default_extension`，并依据 `allow_different_extension` 验证 | 保留规则，完善用户可见反馈               |
| 文件名输入框       | 当前只在 `SaveFile` 模式显示                                                                      | 为打开文件模式补足与系统类似的文件名交互 |
| Gallery 示例       | `gallery/src/pages/window/file_dialog.rs` 的 `OpenImage` 已配置 png/jpg/jpeg/bmp/webp 筛选器      | 更新展示和验收场景，不重复定义底层过滤   |

**关键判断：扩展名过滤的核心业务逻辑已经具备。** 本次不应把“增加筛选器”误解为再创建一个并行业务系统，主要要解决它的可见性、位置、展示内容、各模式交互及边界验证。

## 3. 目标界面

示意布局（结构图，非最终主题配色效果）：

```text
┌─────────────────────────────────────────────────────────────────┐
│ Open Image                                                   ×  │
├─────────────────────────────────────────────────────────────────┤
│  [←] [→] [↑] [↻]  [ C:\...\gallery\src            ] [ Search ] │
│                                                                 │
│  [New folder] [Pin folder]          [Sort ▾]  [Hidden] [System] │
├────────────────┬────────────────────────────────────────────────┤
│ Quick access   │ Name                 Type            Size      │
│                ├────────────────────────────────────────────────┤
│ Home           │ 📁 catalog           File folder               │
│ Documents      │ 📁 assets            File folder               │
│ Downloads      │ 📄 picture.png       PNG file        128 KB    │
│ Desktop        │ 📄 cover.jpg         JPG file         86 KB    │
│                │                                                │
│ This PC        │                                                │
│ C:             │                                                │
│ D:             │                                                │
│                │                                                │
│ Pinned         │                                                │
│ …              │                                                │
├────────────────┴────────────────────────────────────────────────┤
│ 4 entries · 0 selected                                          │

│ File type: [Images (*.png; *.jpg; *.jpeg; ...)      ▾]          │
│                                              [Open] [Cancel]     │
└─────────────────────────────────────────────────────────────────┘
```

### 3.1 顶部：紧凑导航区

- 左侧保留后退、前进、上一级和刷新操作，优先使用**图标按钮**，通过 tooltip 和无障碍名称保留语义，不在按钮旁再写大段英文。
- 中部为可编辑地址栏；点击可编辑完整路径，按 Enter 导航。第一版**不强制实现 Windows Shell 式面包屑**，避免为外观引入另一套路径导航状态。
- 右侧为当前目录搜索框，保持现有名称搜索语义；搜索文本修改后继续走现有查询投影。
- 窄窗口下地址栏弹性收缩，搜索框具有合理最小宽度，不允许导航控件覆盖文件区域。

### 3.2 工具栏

- “新建文件夹”“固定当前目录”放在地址栏下一行，作为次要但易于发现的操作。
- 现有排序入口保留，可置于右侧；“显示隐藏项”“显示系统项”也留在此区域，不再占据底部的文件类型栏。
- 工具栏应避免持续堆叠功能，紧凑窗口需要处理按钮宽度不足的情况。

### 3.3 左侧常用位置

- 按“常用位置／驱动器／已固定目录”分组，并与主列表保持视觉区分。
- 使用已有 location、pinned 数据；不另做系统目录扫描或 Windows Shell 集成。
- 侧栏条目采用普通导航项样式，不再每项都看起来像带边框的大按钮。
- 当前目录在侧栏可对应时显示选中态；长路径截断显示，真实导航仍使用原始 `PathBuf`。

### 3.4 中间文件列表

- 第一版采用 **详细信息视图**，至少包含“名称／类型／大小”；若现有元数据允许，显示“修改时间”。
- 文件夹优先排列，图标与名称左对齐，大小右对齐。文件夹不显示 `0 B` 这种不合适的文件大小。
- 扩展名派生的文件类型可以用 `PNG file`、`TOML file` 等简明描述；不要求调用 Windows Shell 取得系统注册的正式文件类型描述。
- 文件大小使用 B、KB、MB、GB 等可读格式，元数据不可用时显示占位符。
- 列头和排序选择保持一致。若支持点击列头排序，只允许可用的排序方向；缺少相应排序类型时需先明确扩展业务枚举和测试，不能做无效可点击表头。
- 保留现有虚拟列表、稳定 `EntryId`、双击激活、键盘导航及多选语义，不能因增加列和标题而改用一次性渲染所有文件。

### 3.5 底部操作区

底部固定三类信息：

1. 精简状态文本：当前可见条目数量、选择数量或错误提示。
2. 文件名行：与当前模式相匹配的文件名展示／编辑。
3. 文件类型行：需要文件筛选的模式显示筛选器；其下或右侧是主操作按钮与取消按钮。

“打开／保存／选择”是主按钮，取消是次按钮。主按钮的禁用状态必须真实反映当前选择、后台校验和模式要求，而不是仅靠颜色表现。

## 4. 各模式的文件名区域

系统文件对话框的重要操作习惯之一，是**文件名不只是装饰性文本**。本次按模式明确处理：

| 模式              | 文件名区域                                     | 文件类型筛选 | 主按钮 |
| ----------------- | ---------------------------------------------- | ------------ | ------ |
| `PickFile`        | 可编辑；单击文件可同步文件名                   | 显示         | Open   |
| `PickFiles`       | 显示当前多选文件名／数量；第一版可采用只读展示 | 显示         | Open   |
| `PickDirectory`   | 显示当前目录或选中目录，不需要编辑文件后缀     | 隐藏         | Select |
| `PickDirectories` | 显示当前目录选择摘要                           | 隐藏         | Select |
| `SaveFile`        | 保留可编辑文件名                               | 显示         | Save   |

### 4.1 `PickFile` 的输入规则

- 点击列表中的文件，应让输入框与已选文件同步。
- 用户手动输入当前目录内的文件名并确认时，应该按**真实目录项的身份**找到它，并经过现有单文件选择和验证过程，不直接把输入文本当成已验证文件路径返回。
- 匹配不到、目标不是文件、文件在确认前消失时，都应明确拒绝或报告错误，保持对话框打开。
- 对于完整绝对路径、通配符输入以及多文件名语法，**第一版不承诺与 Windows Shell 完全一致**；如后续需要，分别明确契约再扩展。
- 当前 `Filename` action 仅用于 `SaveFile`，不应未经设计就把它的意义扩大到打开模式。优先明确输入框临时编辑状态与已有 selection authority 的关系，再决定是否需要新增公开 API。

### 4.2 `PickFiles` 的多选

- 保留 Ctrl、Shift、Ctrl+A 等原有选择操作和已定义的范围选择行为。
- 多选文件名区域可以展示摘要及部分名称，不必为了模仿原生对话框马上实现解析带引号的多文件名输入。
- 实际返回始终以现有 selection 和 validation 为准，不根据摘要文本反向构造路径。

## 5. 扩展名过滤的用户体验与语义

### 5.1 筛选器显示

当前 `label` 比如 `Images`，建议组合展示成：

- `Images (*.png; *.jpg; *.jpeg; *.bmp; *.webp)`
- `Text documents (*.txt)`
- `All Files (*.*)`

展示层负责拼出 `*.` 前缀；配置中的 `suffixes` 仍是 `png`、`jpg`、`tar.gz` 这样的**不带开头点号**的字符串。保留调用者自定义 label，不强行替换其文案。

若扩展名过多导致下拉项太长，选中区截断即可，下拉列表应尽可能能看清完整描述；实际筛选内容不得随显示截断而改变。

### 5.2 切换行为

- 选择文件类型后立即按现有查询机制重新计算可见条目，**不重新读取目录**。
- 过滤只作用于文件；目录仍显示，以便继续导航。
- 不匹配当前类型的文件从列表消失；已有选择若因此不可见，应由当前选择修复机制处理，不能保留一个不可见但仍可提交的无效文件。
- 搜索、排序、隐藏文件、系统文件开关应与扩展名过滤组合生效。
- 用户选择的过滤器保持既有偏好存储及 session 语义，不为 UI 再增加一份独立过滤状态。

### 5.3 `SaveFile` 的后缀规则

保留当前 `confirmation.rs` 的合同：

- 输入没有扩展名，且当前筛选器指定 `default_extension`：确认目标时补上默认后缀。
- 输入已有后缀且与当前筛选器不匹配：`allow_different_extension == false` 时拒绝，并显示有意义的错误；允许不同后缀时按当前配置放行。
- `All Files (*.*)` 没有默认扩展名时，不凭空增加后缀。
- 切换筛选器不应静默覆盖用户已输入的文件名。
- 文件覆盖确认继续复用已有独立 MessageBox 流程。

### 5.4 边界

继续支持无后缀文件、大小写不敏感匹配和复合后缀（例如 `tar.gz`）；不因本次视觉重构更改过滤算法或原始 Windows 路径的保存方式。

## 6. 标题栏与窗口尺寸

在 `crates/file_dialog/src/window.rs` 的独立窗口构建处：

- 设置 `WidgetryWindowControlsConfig` 的 `maximize_visible` 为 `false`。
- 保留关闭按钮；最小化按钮继续维持当前隐藏状态。
- 默认窗口尺寸建议调整到大约 **960 × 640** 或同级别，实际值以 Gallery 运行效果和最低布局宽度为准。
- **隐藏最大化按钮不等同于禁止用户拖拽调整窗口大小。** 第一版保留当前 `resizable` 的配置语义，除非验证证明确有必要约束最小尺寸。
- 若要求彻底禁用所有系统层面的最大化方式（快捷键、标题栏双击等），需另列为窗口行为需求，而不是把隐藏按钮视为已经完成该能力。

## 7. 主题、焦点与无障碍

- 不在 FileDialog 内硬编码 Light/Dark/Pink Dream/Kamuri Violet 的色值。背景、边框、悬停、选择、焦点和禁用态继续从现有 Theme 与 ColorOverrides 体系取得。
- 新增的布局分组和文本不能破坏原有 Widgetry 样式归属；保留有效 Disabled 与焦点规则。
- Tab 顺序应符合视觉阅读顺序：顶部导航／地址栏／搜索 → 工具 → 侧栏及列表 → 文件名／文件类型 → 主操作／取消。
- 回车在路径栏执行路径导航，在文件名框按对应模式提交；Esc 继续优先关闭局部面板或输入状态，必要时才取消整个对话框。
- 对仅使用图标的导航按钮提供可理解的名称与 tooltip；列表仍保持已有 ListBox 可访问性语义。
- 选择框、按钮与文本布局在 Windows DPI 缩放下不能重叠或裁切。

## 8. 实施范围与文件责任

只修改完成此目标所必需的部分，不借机重构与 FileDialog 无关的 Widget。

| 文件或模块                                                                          | 预期改动                                                                              |
| ----------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| `crates/file_dialog/src/window.rs`                                                  | 最大化按钮显隐、必要的默认窗口尺寸／约束                                              |
| `crates/file_dialog/src/style.rs`                                                   | 主体 Shell 布局；导航、地址栏、搜索、文件区域、底部表单与操作按钮的重新编排；样式同步 |
| `crates/file_dialog/src/controls.rs`                                                | 筛选器下拉展示、顶部工具栏、侧栏分组、与新布局对应的焦点及控件同步                    |
| `crates/file_dialog/src/view.rs`                                                    | 文件列表的列头与行内容、文件类型、大小格式；保持虚拟化结构                            |
| `crates/file_dialog/src/input.rs`                                                   | 新增打开模式文件名编辑时的 Enter、焦点与输入投影                                      |
| `crates/file_dialog/src/model.rs`、`selection.rs`、`confirmation.rs`、`behavior.rs` | **仅在**文件名输入需要调整业务契约时进行必要的最小改动                                |
| `crates/file_dialog/src/filter.rs`、`snapshot.rs`                                   | 优先沿用；若发现过滤边界问题才修改并增加回归测试                                      |
| `gallery/src/pages/window/file_dialog.rs`                                           | 补充演示数据及筛选/模式验证场景，不改变对外模式含义                                   |
| 对应 unit / integration test                                                        | 验证新交互与原有过滤、selection、保存语义                                             |

预计**不需要新增 crate 或外部依赖**；如实现时确有必要，先说明不可由现有模块承担的职责。

## 9. 建议的实施顺序

按业务风险从低到高施工，避免一次性同时重写布局、输入和后台语义。

1. **布局骨架与窗口控件**：隐藏最大化按钮，调整 Shell 层次，将导航、搜索和底部操作区定位好。先以现有控件实现静态正确布局。
2. **筛选器搬迁与描述完善**：将现有 ComboBox 移到文件类型栏，使 label 与扩展名明确可见，核对切换与选中修复。
3. **文件列表外观**：增加列头、类型、可读大小和侧栏分组；保留旧数据绑定及行复用。
4. **文件名交互**：补齐单文件打开模式的输入框同步和确认；多文件/目录模式保持清晰但不扩大语法支持。
5. **焦点、主题、尺寸和性能回归**：覆盖所有模式及主题，在真实 Windows Gallery 中验证并修复视觉/交互问题。

每个步骤完成后确认其可观察行为，不应把“页面能显示”作为交互通过的证据。

## 10. 验证与验收标准

### 10.1 自动化测试

- `Filter`：多后缀、大小写、复合后缀、无后缀和 All Files；非法筛选配置仍按现有规则拒绝。
- `Snapshot`：目录在扩展名过滤下仍可见；过滤与搜索、隐藏／系统开关、排序组合正确。
- `Selection`：切换过滤器使已选文件不可见时，选择和确认状态完成正确修复；不会返回隐藏的旧选择。
- `PickFile` 文件名输入：选中同步、有效名称提交、未知名称拒绝、目录名拒绝、陈旧项拒绝。
- `SaveFile`：默认扩展名补全、冲突扩展名处理、All Files、不允许覆盖时的确认流程。
- 样式或 GUI 相关测试保证布局投影与控件启用/禁用不破坏业务 state。

### 10.2 Windows GUI 验收

在 Widget Gallery 中逐一检查：

- [ ] 标题栏只有关闭按钮，不显示最大化按钮；拖拽缩放行为符合窗口设置。
- [ ] 顶部导航、路径、搜索处于同一紧凑区域；不再占用三行。
- [ ] 侧栏与文件列表视觉上可区分；双击目录、返回上一级均正常。
- [ ] 文件列表的名称、类型、大小可读；文件夹没有误导性的文件大小。
- [ ] 底部文件名、文件类型、Open/Save/Select/Cancel 符合对应模式。
- [ ] `OpenImage` 默认显示图像扩展名过滤，切换 All Files 可看到其他文件。
- [ ] 单文件选择、多文件选择、目录选择和保存结果仍正确。
- [ ] 地址栏 Enter、文件名 Enter、Esc、Tab 和列表方向键按预期工作。
- [ ] Light、Dark、Pink Dream、Kamuri Violet 四套主题的颜色、焦点及禁用态正常。
- [ ] 较小尺寸与 DPI 缩放下控件不重叠、不超出窗口；滚动仍可用。
- [ ] 包含大量目录项时，列表仍按可见范围渲染，没有退化为每帧批量生成全部行。

根据项目规则，GUI 运行时验证优先通过 Gallery 的 BRP 通道；无法通过 BRP 可靠验证的系统窗口行为需人工核对。没有实际运行时，验收项应保持未完成，不写成“已通过”。

### 10.3 工程检查

- 按项目的 `AGENTS.md`、`rules/` 约束进行类型驱动、测试驱动及必要的独立 Code Review。
- 至少进行适用的 `cargo fmt`、目标 crate 测试、Workspace 编译检查，并运行 Gallery 做 GUI 验收。
- Windows 64 位是当前唯一目标环境；不引入为其他平台准备的兼容分支。

## 11. 非目标与后续可选能力

此次**不包括**：

- 替换为 Windows 原生文件对话框或与 Windows Shell 外观完全一致。
- 缩略图视图、文件预览面板、右键系统菜单、拖放或 Shell 图标关联。
- 地址栏路径面包屑的完整交互。
- 在文件名输入框中解析 Windows 风格的多个带引号文件名、通配符或绝对路径选择。
- 为非 Windows 平台设计兼容。

这些能力只有在后续明确提出需求时再实现，不为其预先增加复杂抽象。

## 12. 完成定义

本任务最终交付应是：**一个布局和主要交互习惯接近 Windows 系统文件对话框、保留 Widgetry 主题、隐藏最大化按钮、底部扩展名筛选清晰可用的自绘 FileDialog**。

其中扩展名过滤沿用原有业务实现；打开文件模式的文件名输入是需要补齐的新交互。只有在自动化测试与 Windows GUI 验证完成后，才可把改造标记为完成。
