# Gallery 配置持久化方案

## 1. 配置管理

- 使用 `serde + ron + std::fs`。
- 在 `gallery/src/config.rs` 中实现配置管理。
- 定义 `AppConfig`，实现 `Default`、序列化、反序列化，并作为 Bevy `Resource` 使用。
- `AppConfig::default()` 是唯一的默认值来源，不维护默认 RON 模板，不修改 `build.rs`。

## 2. 配置内容

| 属性 | 默认值 |
|---|---|
| 窗口宽度 | 1920 |
| 窗口高度 | 1080 |
| 窗口缩放比例 | 1.25 |
| 主题 | Dark |
| 语言 | English |

主题和语言需要提供与现有枚举兼容的序列化表示。

## 3. 配置文件路径

固定为可执行文件所在目录下的 `config/config.ron`。

通过 `std::env::current_exe()` 定位，不依赖当前工作目录。

## 4. 启动流程

1. 在创建窗口之前读取并解析配置。
2. 读取成功则使用完整配置。
3. 文件不存在则整体使用 `Default`，并尝试创建默认配置文件。
4. 文件存在但读取、解析或配置校验失败，则整体使用 `Default`，不覆盖原文件。
5. 初始化日志系统后记录此前收集的读取错误及配置创建错误。
6. 使用配置初始化窗口、缩放比例、主题及语言，并初始化对应 ComboBox 的选中状态。

配置生成失败不阻止程序使用内存中的默认配置继续运行。

## 5. 运行时保存

仅在代码明确调用时保存，不自动监听全部 `Resource` 变化。

Gallery 标题栏三个 ComboBox 在实际切换成功后更新 `AppConfig` 并保存完整配置。

- 主题：在延迟命令真正完成主题切换后保存。
- 缩放比例：应用新的窗口缩放比例后保存。
- 语言：完成语言切换后保存。
- 相同选项或初始化选中不触发保存。
- 用户拖动窗口改变尺寸不自动保存。

## 6. 错误处理

- 配置加载失败时不使用部分解析结果。
- 配置文件不存在与配置读取错误分别记录日志。
- 保存失败时记录错误，不回滚已经成功应用的 UI 修改。
- 读取失败时不得覆盖原有的损坏或不可读取文件。

## 7. 验证范围

确认首次启动生成配置、重新启动恢复配置、非法配置整体回退、三个 ComboBox 的持久化行为，以及保存失败时 UI 状态仍然生效。
