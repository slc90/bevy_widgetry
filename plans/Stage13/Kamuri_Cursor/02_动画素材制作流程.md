# 千石冠 Cursor 动画素材制作 SOP

**版本**：v1 / 2026-10-11  
**技术路线**：**仅方案 A**——预合成透明 PNG 连续帧 → 固定网格 Texture Atlas → Bevy 0.20 `CustomCursorImage` 播放。**不采用隐藏 OS 鼠标、用 Bevy Sprite/Node 追踪鼠标的方案 B。**  
**适用范围**：新的千石冠光标动画生产与 QA。此文档描述**素材制作流水线**，不重复项目 `WidgetryCursorPlugin` 的具体接入代码；工程修改请读 `01_Kamuri_Cursor_接入实施方案.md`。

## 1. 固定前提

1. Q 版 C：淡紫色柔软长卷发、安静半垂的蓝眼、头顶**恰好两条向上飘起的深蓝色丝带**；注意手脚数量、关节方向、头发和衣物分离。不是戴皇冠。
2. 光标本体须明确表达实际 GUI 功能。`Pointer` 例外：使用**冠本人直接点击可见按钮**来表达 Pointer，不叠加普通系统箭头。
3. 道具与食物只在合适的 Cursor 使用，且尽量多样；已确定：`Pointer` 糖果、`Wait` 布丁、`Progress` 小蛋糕、`Help` 饼干。其余不强行加食物。
4. **每款光标锁定一个 frame canvas、一个 hotspot、一个动画语义**。帧与帧不能因角色移动而改变图像边界、坐标轴或热点位置。
5. 若用模型制作新姿势，应生成**完整高分辨率透明 RGBA 角色素材 / 必要局部图层**；不要生成含白底、文字、示意小图的海报再假装它是运行时图片。
6. 目标 Windows x64 本机；Bevy 0.20 `custom_cursor` 的图像图集。无须为 Web 兼容性额外设计。
7. 当前 **Pointer、Wait 动画已完成**。其他 12 种动画待按本流程制作。

## 2. 职责边界：模型 vs 代码

| 阶段                                                  | 主要负责者          | 原因/输出                                                              |
| ----------------------------------------------------- | ------------------- | ---------------------------------------------------------------------- |
| 角色初始造型、表情与新增姿势                          | 美术或图像生成模型  | 形成真实可见的插画像素，不能靠普通位移算法凭空创造新的手臂、背景遮挡   |
| 关键帧之间缺失的手、脚、衣物/头发遮挡修补             | 美术或图像生成模型  | 模型输出需**人工验人体与风格**；不要让代码猜被遮住的纹理               |
| 可独立运动的图层裁剪/蒙版                             | 代码辅助 + 人工检查 | 可以通过 Alpha / mask / contour 自动处理，但特殊发丝与半透明阴影需复核 |
| 已分层对象的平移、旋转、缩放、透明度、运动曲线        | 代码                | 可重复、参数可控、无须重新出图                                         |
| 加载圆环/按钮/箭头等几何图形与反馈特效                | 代码为主            | 矢量/像素绘制精确稳定，易保持 hotspot                                  |
| 帧合成、固定 canvas、降采样、透明 PNG 导出            | 代码                | 保持坐标和规格统一                                                     |
| Texture Atlas、元数据、预览 APNG/GIF 和可重复构建脚本 | 代码                | 易 QA、稳定生产                                                        |
| 动画连贯性、身体结构、交互语义、热点真实手感          | 人工验收 + 自动报告 | 程序可以检查格式，不能完全判断动作看起来是否自然                       |

**非常重要**：代码无法保证把 4 张完整扁平人物图“智能补间”成 12 张自然的动作。直接逐帧硬切会有跳动；用整张人物 Crossfade 则会出现双脸/鬼影。稳妥做法是 **相同角色位置对齐 + 真实局部拆层/位移 + 在必要处多补关键姿势**。如果素材条件不足，应让 Codex报告缺少哪种姿势或图层，而不是制造假流畅。

## 3. 通用生产流水线（先验收关键帧，再批量生成）

### Step A — 明确动画合同

为每个 Cursor 写明：

- `semantic`：对应哪种 OS/Widgetry 光标语义。
- `pose_beats`：3～6 个动作节点和功能意义。
- `source_art`：得到批准的静态设计参考和新关键姿势/图层。
- `fps`、`frame_count`、`loop`：初版少帧优先，避免无意义的大量生成。
- `hotspot_anchor`：玩家实际点击/拖动位置，而不是图片视觉中心。
- `enter` / `exit`：进入或退出该 Cursor 语义时是否重置播放。
- `size`：母版与运行时正方形画布尺寸（Pointer 是 320→128，其他动画可以不同，但同一动画内部必须统一）。
- `fallback`：单张透明静态图；如果 atlas 无法应用，OS `SystemCursorIcon` 的安全回退。

### Step B — 制作少量「真正不同」的关键姿势

优先 3～5 个关键姿势，不是一上来让模型生成 24 张全帧。要求：

- 一次生成内容应**只包含一个帧中的完整角色或必要的独立图层**，透明背景、无说明文字和分割边框。
- 角色脸、瞳色、服装的主要结构、两条上飘丝带保持一致；不要出现额外手脚。
- 每张按钮/圆环的位置都能对齐统一 anchor；确定哪只手参与动画，另一只手的位置合理。
- 必须能清楚看见触发点：按下按钮、抓紧、平移、缩放；不要“可爱但不表达功能”。
- 可以有轻微动作夸张，但镜头视角、头部大小不要在帧间突然变化。
- 有完全透明的像素区域和有效 RGBA Alpha；带背景的概念板不能直接进入导帧步骤。

**Pointer 已有样板**：`pointer_animation/keyframes_original/` 下 4 张透明大图，以及 `frames_master_320/` 下已组合好的 12 张帧。优先复用它们验证 pipeline，而非重新让模型画。

### Step C — 分层与统一对齐

建议的图层（按需，不要求每款固定五层）：

- 不动的功能锚定层：按钮/箭头中心/圆环中心；
- 人物主体：脸、身体、服装、常态头发；
- 真正移动部件：手臂、前景手、勺子、发梢、两条丝带；
- 附属道具：糖果、布丁等；
- 临时反馈层：点击亮光、缩放曲线、轻微挤压或激活动效。

1. 锁定一套绝对 canvas 与固定 hotspot 坐标；**不要每帧独立 trim 或中心对齐**。
2. 将锚定层先摆好。以 `Pointer` 按钮的中心为对齐基准、`Wait` 加载环的中心为基准。
3. 若图层需要独立旋转/平移，必须先补画因分离而露出的遮挡区域。
4. 确认所有帧的动作范围都留有 padding，不让头发/丝带/道具被裁剪。
5. 对独立部件使用曲线插值；优先 ease-in/out 或轻微 squash-and-stretch，禁止肉眼明显的全身漂移。

### Step D — 导出透明连续帧

绘制每个时间点的场景并合成 RGBA 图片；每帧分辨率严格一致。以 Pointer 的当前候选为例：

```text
pointer_animation/
├── frames_master_320/
│   ├── pointer_00.png
│   ├── pointer_01.png
│   └── ... pointer_11.png
├── frames_runtime_128/
│   ├── pointer_00.png
│   └── ... pointer_11.png
├── pointer_atlas_128.png
├── pointer_atlas_master_320.png
├── pointer_static_128.png
├── pointer.meta.toml
├── pointer-build-manifest.json
└── previews/
    ├── pointer_preview.gif
    ├── pointer_preview.apng
    └── pointer_hotspot_check.png
```

- PNG 需要 `RGBA`、Alpha 通道，画布边缘透明；不允许海报文字、全局白底和辅助标识。
- 输出无发丝裁切、白边、黑边和莫名的半透明噪点。
- 放缩尽量从较高分辨率母版一次性做优质采样，不要对已经缩到 64 px 的小图连续重复缩放。
- 任何人眼看到的按钮中心、ring center、点击点，在不同帧里必须围绕同一个绝对 hotspot。**视觉按钮凹陷可以动，操作锚点不能随之跳。**
- 预览时必须分别在浅色和深色底上检查半透明边缘。

### Step E — 代码生成图集与元数据

默认按「行主序」打包（从左到右、从上到下）。Pointer：4 列 × 3 行，128×128 每帧，整体 512×384。

**本包自带可执行脚本**（需要 Python 3 + Pillow）：

```bash
python scripts/build_pointer_atlas.py --pointer-dir pointer_animation
```

可以试验其他运行时尺寸，但 hotspot 需按新尺寸重新校准，例如：

```bash
python scripts/build_pointer_atlas.py \
  --pointer-dir pointer_animation \
  --size 96 \
  --hotspot-x 33 \
  --hotspot-y 81
```

脚本做的事是：输入 12×320 RGBA、验证透明、缩放、组合、检查所有帧的图集像素一致、生成图集+单帧 fallback + 元数据 + hotspot 检查图 + SHA256 源清单。

**注意**：这个脚本只负责 **Pointer 已经有完整 RGBA 12 帧之后的后处理**，它不会生成新的人物姿势或自动生产其他动画。未来其他 Cursor 可让 Codex 按同样原则提取通用构建器，**只在有实际第二个使用者之后再考虑抽象化**。

### Step F — 帧预览和 QC

先导出高清 APNG 作为最可靠的透明动画预览，另导 GIF 便于打开（GIF 可能量化色彩、失去半透明边缘）。

QC 按三个层次：

- **美术**：每帧都是同一千石冠；至少 2 个独立可辨别的脚/手（若画面露出），无融合，无怪异的发丝跳动；正好两条头顶丝带。
- **动画**：帧切换无突然「大小变化、位置闪跳、双影」；无头发跨边界；首尾循环自然；实际功能对象被点击、拖动或改变，而不是只有装饰在晃。
- **程序格式**：网格大小/索引顺序、RGBA/Alpha、12 帧数量、帧率、frame0 fallback、hotspot 坐标合法、Atlas crop 与源帧字节级像素一致。

若动画动作本来不顺，必须回到 Step B/C 修关键姿势，不能用模糊图像过渡掩盖。

### Step G — 与 Bevy 集成

1. 注册正式 png 内嵌路径和语义标识，加载 `Handle<Image>`。
2. 使用 `CustomCursorImage` 的 `texture_atlas: Some(TextureAtlas {layout, index})` 与 `hotspot`；每帧只更新 index。
3. 由 Cursor 协调器统一管理状态，不要在每次刷新 hover 时重建第 0 帧。
4. Bevy 的 `WinitSettings::desktop_app()` **不会持续更新 Timer**；仅在真实播放中通过事件循环唤醒/`RequestRedraw` 等策略推进帧。
5. Window/native drag 等特殊场景暂停光标更新，主题关闭退回 `CursorIcon::System`。
6. 必须用 **Windows 实际 OS Mouse** 校准 hotspot，BRP Custom Pointer 不能替代。

## 4. Pointer 的已确定动画规范

| 字段          | 约定                                                     |
| ------------- | -------------------------------------------------------- |
| `semantic`    | `Pointer` / 系统可点击区域                               |
| 动画内容      | 冠本人伸手点击一个明显蓝色按钮，旁边有小糖果             |
| 姿势节奏      | 准备 → 下压中 → 按到底 → 回弹恢复                        |
| 播放          | 12 帧，8 FPS，1.5s 无限循环                              |
| 类型          | 悬停后持续循环，不要求实际鼠标按下才动                   |
| 当前画布      | 320×320 RGBA 母版，128×128 RGBA 候选运行时               |
| 图集          | 4×3、每格 128×128、总 512×384                            |
| hotspot       | `[44,108]`（候选，按钮中心；实际 Windows 真鼠标微调）    |
| 进入          | 首次进入 Pointer 从第 0 帧开始；语义没变不重启           |
| 退出          | 当逻辑 Cursor 改变时立刻停播                             |
| 单帧 fallback | `pointer_static_128.png`，资源尚未可用时退到系统 Pointer |

`pointer.meta.toml` 是本项目可自定义读取的**示意配置格式**，不是 Bevy 自带会自动加载的 Cursor 元数据。Codex 可以按真实工程需求将其转换为 Rust 常量/表，不要求运行期引入 TOML parser。

## 5. 动画制作进度、优先级和约束

已确定的第一档合计 14 种，Pointer、Wait 已完成，其余 12 种待制作：

| 光标                    | 主要动作                           | 适合由代码制作的部分                           |
| ----------------------- | ---------------------------------- | ---------------------------------------------- |
| `Wait`（已完成）        | 冠趴在加载圆环上，偶尔吃一口布丁   | 圆环旋转、勺子局部位移、眨眼（须真实眼部素材） |
| `Progress`              | 冠抱着箭头和小蛋糕，表示后台执行中 | 进度环旋转/亮暗，蛋糕轻微移动                  |
| `Help`                  | 冠捏饼干歪头思考                   | 问号浮现、呼吸式轻动                           |
| `Grab`                  | 伸手准备抓住目标                   | 手臂前伸动作的插值                             |
| `Grabbing`              | 抓紧后用力拖动                     | 力度/身体前后位移                              |
| `DragSort`              | 上下移动条目                       | 列表项上下换位                                 |
| `InsertDrop`            | 项目插入两项之间                   | 插入线/位置间隙变化                            |
| `ReplaceDrop`           | 冠抱着新物品替换旧物品             | 旧项淡出、新项滑入（人物需补关键姿势）         |
| `ZoomIn`                | 放大镜中内容放大                   | 镜片中的局部缩放                               |
| `ZoomOut`               | 放大镜中内容缩小                   | 镜片中的局部缩放                               |
| `HorizontalValueAdjust` | 左右调整滑块                       | X 方向位移                                     |
| `VerticalValueAdjust`   | 上下调整滑块                       | Y 方向位移                                     |
| `Panning`               | 拖动画布/视图                      | 背景平移、方向反馈                             |

**未完成项的顺序只是未来制作顺序候选**。要为另一个 Cursor 制作新动画时，应先检查已有静态参考与透明母版：如果只有海报参考，第一步是补素材，不是马上运行打包脚本。

## 6. 每制作一个新动画的交付验收模板

建议 Codex 生成下列产物，并单独报告状态：

```yaml
cursor: <semantic>
art_source: <approved-original>
reference_board: <path>
keyframe_sources:
  - <path>
master_frame_size: [320, 320]
runtime_frame_size: [128, 128]
frames: 12
fps: 8
loop: true
hotspot: [44, 108]
hotspot_validation: provisional # real_windows_mouse_checked / provisional
art_qc: pending # passed / failed / pending
animation_qc: pending # passed / failed / pending
format_qc: pending # passed / failed / pending
bevy_test: pending # passed / failed / pending
native_mouse_test: pending # passed / failed / pending
```

其中帧数、大小、hotspot 是示意，**不同光标不能机械复用 Pointer 的 `[44,108]`**。

Codex 最终应交付完整透明帧、atlas、metadata、可视化 APNG、格式检查报告，并说明哪些额外关键姿势需要模型/美术完成。通过 QC 才可加入主题 mapping；不合格时坚持 fallback，不把预览图当正式素材。
