# 04 · 补齐普通控件的按下、拖动和取消闭环

## 目标

补齐经测试证实的按下、拖动、取消和指针失效边界，同时保留正常业务行为。

## 范围

负责 Table、ListView、包装控件及组合场景的必要修正和双身份回归；排除原生 Window move/resize，不进行无差别重写。

## 预期产出

按会话 ownership 幂等收尾的普通交互，以及每个生产修改对应的失败用例和回归证据。

## 与前后方案的关系

承接测试基础及通用状态；下一方案将这些本地结果与新版 BRP 接到真实 Gallery 中验收。

本文件是顺序执行链中的第 4 份，具体位置见 [总览](00-overview.md)。需要查看完整设计时，使用 [总方案](../master-plan.md)。

### 共同边界

普通鼠标类交互统一消费 Bevy 的 `PointerInput`、`Pointer<T>`、`PointerId`、HoverMap 和相关派生状态。不在控件中识别 BRP UUID，不把 Mouse 事件另接一条业务路径；真实鼠标仍通过 `PointerId::Mouse` 进入同一套交互。keyboard、IME、剪贴板和应用业务输入不被强行改成 Pointer。

用户限定 BRP 与真人不会同时操作。不设计多人并发，也不设 Mouse 永久优先规则。但源交接、指针注销、旧 hover、按下和拖动的清理仍是必要范围；静止的旧指针也可能留在 HoverMap。BRP 负责虚拟源的激活、退场与真人交接，Widgetry 负责通用 Pointer 消费，不修改宿主 raw mouse 资源或操作系统光标。

**Native Window move/resize 保持现状。** `crates/window/src/title_bar/drag.rs` 与 `crates/window/src/title_bar/resize.rs` 中的原生拖窗、窗口 resize、现有真实按键收尾和系统 cursor 处理不改；不增加 Custom 拒绝分支，不加程序化虚拟拖窗/缩放，不替换 Win32/winit 行为。BRP 验收不操作这些拖拽区域。现有 observer 仍可能接到 Custom Press，保持代码不变不是新增了一道隔离保护。[W3] [W4]

Table 列宽、滚动条 thumb、文本选择属于普通控件拖动，仍在范围内。窗口中的普通按钮、最小化/最大化/关闭 controls、modal blocker 和 FileDialog 正文也没有因位于 Window crate 就全部被排除。统一交互不等于重写所有控件，不改 selection/value/focus 的既有业务契约，不用直接触发 Activate、修改 Value 或 ScrollPosition 冒充输入验证。

生产 Widget crate 不新增 BRP 依赖，也不 fork Bevy。共享适配留在现有 `core`，测试工具留在 `test_utils`，外部 BRP 只由 Gallery 消费。执行总顺序固定为配套 BRP 01 → 02 → 03 → 04 → 05 → 06，再执行本仓库 01 → 02 → 03 → 04 → 05。只有最后接入需要 BRP 已形成固定版本，前面的排序是统一交接顺序，不是假设技术硬依赖。

共享状态遵循唯一写入者原则：统一适配官方 Hovered/DirectlyHovered，而不是保留 Mouse-only writer 再每帧覆盖。普通会话只由其 PointerId 对应的终止或失效信号清理，取消不能产生成功 Click/Drop，正常 Release 也不能因提前清除 Pressed 而丢失 Activate。真实鼠标回归与 Custom 回归使用同一行为断言，但直接触发目标事件、真实 Picking 和桌面验收是不同层次的证据。

## 方案正文

### 改的是终止边界，不是所有业务行为

保留普通控件已经使用的 Pointer observer、Activate、ValueChange 和内部 state 机制。Button/CheckBox/RadioGroup 不重写为直接监听 raw input 的控件；ListView 继续以 stable item ID 防止虚拟行复用误激活；Table 继续保存列宽操作的 pointer 和列 identity；TextField 继续复用官方 EditableText 的命中与文本选择。[W5] [W6] [W8] [W9] [U4]

对当前源码做本地完整符号扫描，区分生产行为、输入适配、原生例外、测试默认值和文档。检查 `PointerId::Mouse`、`is_mouse()`、`CursorMoved`、`MouseButtonInput`、`MouseMotion`、`MouseWheel`、`ButtonInput<MouseButton>`、`cursor_position()`。不能把不完整的 GitHub 搜索零结果当作证明，也不能全局替换 Mouse 字样。`MouseScrollUnit` 只是单位，keyboard 的 ButtonInput<KeyCode> 也不属于要清除的路径。

### 已发现的 Table 边界

`table/resize.rs::on_cancel` 需要事件一路到 Table root，并要求 original target 能解析到本次 session.handle。当前写法在高层 Cancel 明确发给原始 handle 时能匹配，但如果 pointer 已移到别处、输入层取消没有对旧 handle 派发事件，就可能无法结束会话。这里是基于源码的风险判断，尚未运行复现；用前面的真实管线 fixture 固定结论后再落改动。[W9] [U3] [U5]

Table 的终止依据应是本次会话的 PointerId 和有效性，而不只依赖此刻 hover 哪个 handle。保留正常 Pointer<DragEnd>、Pointer<Cancel> 路径，并对输入级 Cancel、pointer 注销/位置失效、相关窗口或目标实体消失提供收尾。取消调用现有取消路径，保留已提交列宽，不伪造正常 End、Drop 或额外 selection 通知。同一会话只产生一次 terminal 通知，旧消息不结束新会话。

这里可修改 `crates/table/src/resize.rs` 与必要的注册排程，**不能误改同名的 `crates/window/src/title_bar/resize.rs`**。

### 其他持有状态的控件

ListView 已有 PointerId ownership，核对它在输入级 Release/Cancel、指针消失、禁用和虚拟行复用后的清理是否完整；不因名字已是 Pointer 就跳过。这类状态仍须绑定原始 item identity，不能交接后在回收复用的新行上补一次 Click。[W8]

官方 Button 的 Pressed 主要由 Release、DragEnd、Cancel observer 清理，并不因为叫 Pointer 就保证所有异常退场都会收到这些高层事件。因此对 Widgetry Button、Checkbox、Radio、ScrollArea thumb 和组合控件检查输入取消、失效后的 Pressed/drag 状态。配套 BRP 会在源侧补足其取消通知，但 Widgetry 的通用状态不能永久依赖某个具体自动化库替它清理。[U6]

确实需要补充时，按控件的实际会话保存 PointerId，用输入级 Cancel 或 pointer 失效清理**该会话拥有的状态**。对于官方 headless 组件的 Pressed，可在 Widgetry 包装层增加小的 ownership/清理适配，不替换官方正常点击、键盘或值变更实现。不能一见任意 Cancel 就删除全 App 的 Pressed，也不能清除另一个控件的键盘/程序状态。

存在高层 Cancel 和输入级兜底两条终止入口时，共用幂等收尾，不能重复通知。正常 Release 要保留 Bevy 的 Click/Activate 派发顺序；输入级兜底不能提前删除 Pressed 导致官方 Click 不再激活。必要的最终清理排在当帧交互派发和 deferred commands 之后。

### Focus、组合控件和原生例外

Custom Press 获得的 InputFocus 是 App 内 focus；不需要伪造 OS 前台窗口，也不重写 `window/input.rs` 的多窗口 keyboard/IME 路由。验证 TextField 单击定位、双击选词、拖动选择、ReadOnly 和 disabled；保留同一 App 内只维护既有 focus 机制，不新增每只 pointer 一份键盘焦点。[U4] [W13]

ComboBox、Tree、MessageBox、FileDialog 重点验证组合的行为：弹层打开/关闭、outside click、选择、滚动、modal 阻挡、secondary window 内的输入目标和关闭后的旧实体清理。生产代码只有在查出真实的 Mouse-only 条件或终止缺口时才修改；不能仅因纳入回归就重写这些 crate。Waveform 若某路径只是绘制、数据更新或程序控制，保持不动。

Native Window 两个原生操作文件保持原样，包括现有 `ButtonInput<MouseButton>`、start_drag_move/start_drag_resize 和 cursor icon 行为。它们是有意保留的例外，不是扫描不彻底。窗口控制按钮属于普通 activation，可以从共享 hover 与普通 Pressed 清理获益，但不能因此改动原生 drag/resize 算法或插入 Custom 身份过滤。[W3] [W4]

### 验收和产出

这一部分交付已证实必要的普通控件修正，以及相应双身份回归。每个生产改动都对应失败用例；没有问题的 observer 保留。验收同时看成功动作和取消动作：正常点击只激活一次，取消不激活；正常拖动有唯一 End，取消有唯一 Cancel；没有残留 Pressed、拖动会话或过期目标。

有受保护的原生代码差异检查，确保两份文件及其装配逻辑没有被重写。真实鼠标原生拖窗和窗口 resize 由人工确认保留原体验，不把 Custom Pointer 的测试当作它们通过的证据。对每个未运行的 GUI 情形明确记录，不从单元测试推断全部桌面行为。
