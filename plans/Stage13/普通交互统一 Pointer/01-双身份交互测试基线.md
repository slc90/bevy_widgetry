# 01 · 建立 Mouse 与 Custom 共用的交互测试基线

## 目标

建立 Mouse 与 Custom 共用的行为断言和真实 Picking 测试基础，记录尚未修复的差异。

## 范围

负责 test_utils 通用构造、输入级 fixture、已有 Mouse 默认 helper 保留与失败基线；不同时改造所有生产控件。

## 预期产出

可复用的双身份测试入口、真实命中 fixture 和有证据的基线。

## 与前后方案的关系

按总执行顺序承接 BRP 的固定版本交接，但本地 fixture 本身不依赖 BRP；下一方案用这些用例固定共享 hover 语义。

本文件是顺序执行链中的第 1 份，具体位置见 [总览](00-overview.md)。需要查看完整设计时，使用 [总方案](../master-plan.md)。

## 基线与共同约束

版本：方案草案 1，2026-10-05。

核对基线：`slc90/bevy_widgetry@f32f5d0452cf8d63b6d506dc1060236e70367dd5`（本次读取时的 `main`）。配套 BRP 基线为 `slc90/bevy_brp@7eb70b5d24a19b8e7480b11bc1726af4e80cce6c`。Widgetry 固定 Bevy `=0.19.1`，Gallery 当前消费 BRP `v0.2.2`。源码通过 GitHub 连接器核对；上游行为核对到 Bevy `v0.19.1`，不把当前讨论中的判断当作已经验证的实现。[W1] [W2]

这是待实施方案。本次只生成文档，没有改仓库，没有运行编译、测试或真实 Gallery。正文中的共享 Pointer 适配、owner 状态和新的测试入口是方案设计；现状与设计分开说明。

### 共同边界

普通鼠标类交互统一消费 Bevy 的 `PointerInput`、`Pointer<T>`、`PointerId`、HoverMap 和相关派生状态。不在控件中识别 BRP UUID，不把 Mouse 事件另接一条业务路径；真实鼠标仍通过 `PointerId::Mouse` 进入同一套交互。keyboard、IME、剪贴板和应用业务输入不被强行改成 Pointer。

用户限定 BRP 与真人不会同时操作。不设计多人并发，也不设 Mouse 永久优先规则。但源交接、指针注销、旧 hover、按下和拖动的清理仍是必要范围；静止的旧指针也可能留在 HoverMap。BRP 负责虚拟源的激活、退场与真人交接，Widgetry 负责通用 Pointer 消费，不修改宿主 raw mouse 资源或操作系统光标。

**Native Window move/resize 保持现状。** `crates/window/src/title_bar/drag.rs` 与 `crates/window/src/title_bar/resize.rs` 中的原生拖窗、窗口 resize、现有真实按键收尾和系统 cursor 处理不改；不增加 Custom 拒绝分支，不加程序化虚拟拖窗/缩放，不替换 Win32/winit 行为。BRP 验收不操作这些拖拽区域。现有 observer 仍可能接到 Custom Press，保持代码不变不是新增了一道隔离保护。[W3] [W4]

Table 列宽、滚动条 thumb、文本选择属于普通控件拖动，仍在范围内。窗口中的普通按钮、最小化/最大化/关闭 controls、modal blocker 和 FileDialog 正文也没有因位于 Window crate 就全部被排除。统一交互不等于重写所有控件，不改 selection/value/focus 的既有业务契约，不用直接触发 Activate、修改 Value 或 ScrollPosition 冒充输入验证。

生产 Widget crate 不新增 BRP 依赖，也不 fork Bevy。共享适配留在现有 `core`，测试工具留在 `test_utils`，外部 BRP 只由 Gallery 消费。执行总顺序固定为配套 BRP 01 → 02 → 03 → 04 → 05 → 06，再执行本仓库 01 → 02 → 03 → 04 → 05。只有最后接入需要 BRP 已形成固定版本，前面的排序是统一交接顺序，不是假设技术硬依赖。

共享状态遵循唯一写入者原则：统一适配官方 Hovered/DirectlyHovered，而不是保留 Mouse-only writer 再每帧覆盖。普通会话只由其 PointerId 对应的终止或失效信号清理，取消不能产生成功 Click/Drop，正常 Release 也不能因提前清除 Pressed 而丢失 Activate。真实鼠标回归与 Custom 回归使用同一行为断言，但直接触发目标事件、真实 Picking 和桌面验收是不同层次的证据。

## 方案正文

### 已核实的现状

`Button` 的样式读取 `Hovered`、`Pressed`，行为复用官方 ButtonPlugin；CheckBox 复用官方 Checkbox；ComboBox 的 field 使用普通按钮，outside click 监听 Pointer<Click>。ListView 的 `PressedEntry` 和 Table 的 `ResizeSession` 已保存 PointerId，Table 的列拖动已使用 Pointer<Drag>，TextField 的鼠标定位与选择复用官方 EditableText 的 Pointer observer。[W5] [W6] [W7] [W8] [W9] [U4]

这些事实只说明事件接口已经接近设备无关，**不说明整个链路已经支持 Custom**。特别是 Bevy 0.19.1 的 `update_is_hovered` 与 `update_is_directly_hovered` 都显式使用 `HoverMap[PointerId::Mouse]`；普通按钮即使收到 Custom Click，Hover 样式也不会自动跟着工作。Tooltip 自身还另外写死了 Mouse。本方案不能沿用先前“普通控件全都不用改”的假设。[U1] [W10]

### 测试工具先区分两种证据

现有 `crates/test_utils/src/pointer.rs` 把 PointerId 写成 Mouse，且主要直接构造/触发目标事件。它适合 observer 单元测试，不证明 PointerInput、Picking backend 或真实命中正确。`test_utils/src/lib.rs` 也已经说明这个边界。[W11] [W12]

为现有 helper 增加可以指定 `PointerId`、`Location`、目标及必要 payload 的通用入口。原来的 `primary_press`、`primary_click` 等便捷入口可以继续作为 Mouse 默认封装，避免无关测试大规模改名；测试默认值不是生产逻辑写死 Mouse。新测试使用确定性的 Custom UUID，不依赖真实 BRP 的 UUID，也不引入 BRP crate。

另建真正从 `PointerInput` 进入的 headless UI/Picking fixture：安装实际所需插件、明确 Window/Camera/Node 尺寸、规范化 target 和布局，再推进输入与命中阶段。它不能用修改 HoverMap 或直接 trigger Click 替代整个输入链。允许一个更小的 HoverMap fixture 只测 hover 投影，但要明确它不覆盖 backend。[U2] [U3]

### 基线和回归用例

同一组普通交互分别用 Mouse 和 Custom 运行，比较业务通知、视觉状态、selection、focus 和终态，不要求两个 pointer 同时运行。基线应捕获 Custom hover 失效、Tooltip 忽略 Custom、按下后移开再取消、pointer 位置失效和实体被销毁等问题。尚未修复的断言可以作为后续方案的失败基线，不能先改断言来制造通过。

至少包含一次首次定位再点击、无新 Move 的点击、按下与释放不同帧、双击计数、拖动终点、离开目标、取消、滚动、disabled、父子命中和多窗口 target。不要把 Press 和 Release 在同帧一次写完后，把偶然成功当作真实交互；上游 Release/Click 使用上一帧 hover，命中又只看当帧最终位置。[U3]

取消测试同时区分输入级 `PointerAction::Cancel`、框架派发的 `Pointer<Cancel>` 与指针直接失效。上游普通管线会过滤 Cancel 指针的 hits，而 Cancel observer 又只遍历当前 hover；因此不能只直接 trigger 一个高层 Cancel 来证明输入级取消已经覆盖了所有持有状态。[U3] [U5]

### 产出与约束

产出是设备无关的测试构造入口、真实 Picking fixture 和已记录的基线。范围主要是 `crates/test_utils/src/pointer.rs`、`scene.rs`、`lib.rs`、相关 Cargo 依赖和直接相关测试；UUID 依赖只为构造 Custom ID 使用最小配置，生产 Widget 不因测试新增自动化依赖。

不在这个方案里同时修所有生产控件。后续共享 hover、Tooltip 和交互终止方案各自消费这些失败用例。每次推进 App update 的位置要能解释，不靠任意 sleep 掩盖时序。现有 Mouse helper 默认行为与真实鼠标回归保留。
