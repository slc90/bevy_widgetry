# 迁移现有 Window 调用方并同步公共契约

## 目标

把新的强制 `WidgetryWindowBackground` 构造参数完整传播到现有消费者，保持原有业务语义不变；同时更新 Window crate 的公开说明，使“背景是构造期配置”成为明确契约，而不是只存在于实现细节中。

## 范围

本方案负责：

- 现有 `widgetry_window(...)` / `owned_widgetry_window(...)` 调用点迁移；
- MessageBox 内部窗口继续固定使用 Theme 背景；
- 相关 Window / MessageBox 测试构造代码适配新签名；
- `crates/window/src/lib.rs` 文档同步；
- facade 导出边界确认；
- 不为旧签名增加兼容设计。

Gallery 的可视化接入放在下一方案。

## 预期产出

Workspace 内已有消费者全部显式选择背景，不存在依靠旧默认行为的调用点；MessageBox 的公开 API 保持不变；新增背景类型通过现有 facade 自然导出。

## 与前后方案的关系

前两个方案已经给出完整 Window 背景能力。本方案把这个新契约传播到现有代码，使后续 Gallery 和测试不需要同时面对旧、新两套调用方式。

---

## 不保留兼容入口

两个构造函数已经改为强制：

```rust
background: WidgetryWindowBackground
```

Workspace 内所有旧调用都直接迁移。

原来依赖纯色主题背景的地方统一显式写：

```rust
WidgetryWindowBackground::Theme
```

不增加：

- `widgetry_window_with_background(...)` 之类第二套命名；
- 旧签名 wrapper；
- builder 只为了模拟 Rust 默认参数；
- `Default` 背景来隐藏调用方选择。

这符合本次已经确定的原则：不要为了兼容现有代码增加设计。

## Window crate 内部测试与调用

`crates/window` 自身的测试中存在大量：

```rust
widgetry_window(...)
owned_widgetry_window(...)
```

这些现有测试在不验证图片背景时，全部显式补：

```rust
WidgetryWindowBackground::Theme
```

现有测试覆盖的 native 属性、camera 绑定、duplicate binding、WindowClosed、controls、owned lifecycle、modal blocker、resize handle 等行为不因本次背景能力改变语义。

背景能力专项测试放到最终测试方案里新增，不用把所有旧测试改写成图片场景。

## MessageBox

`WidgetryMessageBox` 内部当前通过：

```rust
owned_widgetry_window(...)
```

创建自己的 native window。

这里显式传：

```rust
WidgetryWindowBackground::Theme
```

因此 MessageBox 继续保持当前行为：

```text
窗口背景固定使用 Widgetry Theme
正文和按钮继续按现有主题逻辑更新
modal lifecycle 不变
```

`widgetry_message_box(...)` 的公开 API 不增加背景参数。

本次不把 Window 图片背景能力顺手扩展成 MessageBox 的新配置能力，也不增加 MessageBox opacity、image 或 mode 参数。

## MessageBox 测试

`crates/message_box/tests/*` 中也有直接构造 parent Window 的代码，例如通过：

```rust
owned_widgetry_window(...)
```

创建测试 parent。

这些位置同样显式传：

```rust
WidgetryWindowBackground::Theme
```

现有 MessageBox 测试仍然负责原来的结果、modal ownership、关闭、重复 activation、Theme 等行为；新背景能力不能破坏这些测试。

## Window crate 文档

更新 `crates/window/src/lib.rs` 的公开说明，至少明确：

- Widgetry Window 背景在构造时选择；
- 支持 Theme 或 Image；
- Image 支持 `Stretch` / `Cover`；
- Image 可以在构造时指定整体 `opacity`；
- 图片未加载时背景透明；
- Image 本身不响应 ThemeChanged；
- Window border 与 TitleBar border 仍按现有 Theme 行为更新；
- 运行时不支持切换背景、替换图片、修改 mode 或 opacity。

现有 transparent native window、专用 camera、owned/borrowed lifecycle 等文档继续保留，不因为新增背景而弱化原契约。

## facade

`crates/bevy_widgetry/src/lib.rs` 当前已有：

```rust
pub mod window {
    pub use bevy_widgetry_window::*;
}
```

新增公开背景类型可以通过现有 facade 自然导出。

不增加额外 facade wrapper，也不重新设计 `bevy_widgetry::window` 的组织方式。

## 与 Theme 的跨模块边界

迁移过程中要保持已经确定的区别：

```text
Theme Window
→ BackgroundColor 跟随 Theme
→ Window border 跟随 Theme
→ TitleBar border 跟随 Theme

Image Window
→ image / mode / opacity 不跟随 Theme
→ Window border 仍跟随 Theme
→ TitleBar border 仍跟随 Theme
```

不能为了让旧 Theme 测试容易通过而给 Image Window 偷挂 `BackgroundColor`。

## 不扩展 runtime Widget API

背景配置属于一次性构造 Props/参数，不是 Window 自有 runtime state。

本次不增加：

- `set_background(...)`；
- `set_background_image(...)`；
- `set_background_mode(...)`；
- `set_background_opacity(...)`；
- 背景变化 event。

后续如果真的出现运行时修改需求，再单独设计，不在本轮借 API 迁移顺手加入。
