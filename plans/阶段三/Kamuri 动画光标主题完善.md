# Kamuri 动画光标主题完善：统一任务说明

## 目标与自主权

将 `bevy_widgetry` 现有的 Kamuri 光标主题完善为一套可以在真实 Windows GUI 中使用、在 Gallery 中完整展示、并可由通用 Skill 持续扩展的动态光标系统。

本文件是一份**统一的目标与验收说明**，不是按提交拆分的实施计划。由 Codex 自行调研、规划任务粒度、确定执行顺序、选择工具和制作技术、进行验证及返工；无需预先按本文的章节拆成实施方案。除项目已有工程约束外，不限制使用程序化绘图、矢量设计、图像处理、关键帧、补间、逐帧绘制、外部参考资料或其他适当工具。关键帧与补帧仅是可选方法，不是强制流程。

自主权不等于放宽目标：不能为了赶进度而减少光标覆盖范围、让大量光标沦为同一闪烁模板、跳过真实运行时验证，或用静态预览冒充动画交付。

## 范围与现状

- 当前 Kamuri 覆盖 **45 种语义**：Bevy 0.20.0 的全部 **34 种** `SystemCursorIcon`，加上 Widgetry 自己的 **11 种** `WidgetryCursorHint`。本次**不扩充类型数量**。
- 目前实际动画主要是 `Pointer`（12 帧）和 `Wait`（24 帧），均以 8 FPS 播放；其余使用静态 Atlas。上述帧数、帧率、旧图片仅是现状，不构成新方案的制作限制。
- 当前 Gallery 已有 Cursor 页面，可切换 System/Kamuri 主题，并提供 45 个目标区域；鼠标悬停可触发实际 OS Cursor。展示区域内部的光标图像当前仍依赖静态 Atlas。
- 参考入口：`plans/第三阶段规划.md`、`docs/crates/cursor.md`、`crates/cursor/src/`、`crates/asset/src/`、`gallery/src/pages/cursor.rs`。开始时应以最新代码为准，`plans/` 仅作为历史目标参考。
- 保留原有 Cursor 系统职责及语义入口，不转而为每个控件编写独立动画播放器。

## 动画制作要求

### 逐种独立创作

45 种光标**各自设计连续循环动画**。Codex 对每一种分别理解实际用途，选择独有或有明确语义理由的运动语言，不要求共用动画模板。可以自行调整原有造型、颜色细节和装饰元素；旧素材只是设计参考，而不是必须逐像素保留的基底。

视觉目标是：光标语义清楚、Kamuri 风格整体协调、动画有辨识度且适合长期在桌面界面使用。不能为了“45 种都动”而牺牲操作辨识度、可读性或定位精度。

### 尺寸、循环和热点

- **全部光标的输出帧画布统一为 80×80 像素**。不同光标实际可见内容的占比可以不同，避免细长、精确操作类光标过度臃肿；在真实 OS 环境检查视觉重量和大小是否协调。
- 每种光标的**帧数、帧率和循环时长均独立确定**，无须相同，也不受原 Pointer/Wait 参数约束。
- 45 种都要**持续循环播放**，不只在切换语义时播放一次。
- 每种光标的 **Hotspot 在该动画所有帧之间固定**。若重新设计造型，应重新确定合理的热点位置，并确保视觉上的实际操作锚点也不漂移。箭头指尖、文本插入点、十字准星中心、缩放/调整尺寸方向等不能在循环中产生误导性的位移。
- 循环接缝自然；无意外抖动、模糊、裁剪、透明边缘瑕疵或重影。帧画布、透明通道、像素数据及热点应满足当前运行时使用方式。

### 工作方法由 Codex 自主优化

先自行选择几种**具有代表性且差异明显**的光标制作样本，检验 80px 输出、真实 OS 渲染、动画品质、热点和制作工具链。样本验证通过后，再自行推进其他类型；此环节是 Codex 的自主质量门槛，而不是要求用户逐个审批。

允许 Codex 从实际结果反复修改创作工具链、动画方案或输出形式。对技术正确性实行自动检测；对美术品质还应提供可检查的动态图像/预览，不将“脚本执行成功”当作视觉质量通过。

## 运行时集成

完成后的 Kamuri 动画要通过**统一的 Cursor 机制**供应用使用，而不局限于 Gallery。现有控件使用 `EntityCursor` 或 `WidgetryCursorHint` 等语义时，在 Kamuri 主题下应显示对应的真实动画 OS Cursor，包括拖拽、禁用、加载等现有状态优先级与生命周期处理。

需要支持每种动画独立的帧数、播放速率和热点信息；使用何种资源组织方式、播放器结构和调度策略由 Codex 根据现有系统自行确定。保留现有的语义解析、Hover/Lease/Capture、窗口焦点与原生窗口操作时的控制权边界；同一语义持续时播放应连贯，语义变更时正确切换，失焦/退出/无效时正确停止与清理。

不改变调用方明确指定的 `EntityCursor::Custom` 光标。System 主题继续使用系统光标；Kamuri 素材尚未就绪或加载失败时，提供有意义的静态或 System 回退，并避免无意义的持续重绘。

## Gallery 行为

在现有 **Cursor 页面**直接集成 45 种动画，不另造一套脱离实际运行时的展示素材：

- 页面中 **45 个预览全部自动、持续循环播放**，各自按照自己的时序运行；不要求相位或帧率一致。
- 鼠标悬停某个目标区域时，**真实的 Windows OS 鼠标光标**也使用对应的 Kamuri 动画。
- 预览与 OS Cursor 使用相同来源的动画素材和语义映射，避免出现“一种是展示动画，另一种是实际效果”的分叉。
- 切换为 System 主题后，真实 OS Cursor 应恢复系统样式；Gallery 里的 Kamuri 动画预览可以继续播放供对照。
- 离开 Cursor 页面后，应停止该页面的动画预览更新，释放不再需要的页面级工作；不要为了预览让不相关页面持续重绘。
- 允许 Codex 优化预加载、资源组织、帧更新和显示策略，但不能用只播放一部分预览来规避性能目标。

## 真实使用与验收

完成标准不只看资源文件存在，还要看实际操作效果：

1. **覆盖**：45 种语义都有实际循环动画，可在 Gallery 中逐一观察。每种不是把某个统一模板简单贴上去；基本造型与业务语义仍可辨认。
2. **显示**：所有动画帧均为 80×80 画布，实际主体视觉尺寸协调；不会明显超出有效显示区域或在循环中跳动。
3. **精度**：各帧 Hotspot 固定且功能性视觉锚点稳定，真实鼠标点击、文本输入定位、拖拽与 Resize 操作不被动画误导。
4. **集成**：Gallery 的 45 个预览同时循环；悬停可触发真实 OS 动画；其他控件能通过既有 Cursor 语义使用对应动画；主题切换与调用方自定义光标保持原行为。
5. **生命周期和故障**：窗口失焦、语义切换、Hover/Lease/Capture、禁用/加载状态、页面切换、素材不可用等情况没有错误的光标残留或无效重绘。
6. **性能**：45 个预览同时运行时无明显卡顿；普通页面仅为实际需要的光标动画付出更新开销。由 Codex 结合工程现有测试、Benchmark、Gallery/BRP 能力进行验证。
7. **可核查证据**：留下可供直接检查的完整动画预览和必要的测试/验证结果。涉及 OS 原生光标视觉与热点行为，应在真实 Windows 环境检查；不能把模拟 Pointer 或 Headless 测试当作等价替代。无法实际验证的项目要明确说明，不可声称已通过。
8. **文档**：同步维护受影响的 `docs/crates/cursor.md`、Gallery 文档、素材说明或其他直接受影响文档；实际开发遵守仓库 `AGENTS.md` 和相关 `rules/`。

## 最终沉淀通用动画光标创作 Skill

全部动画及运行时集成经过实际检验之后，再由 Codex 将**真正验证有效的制作经验**整理为一份**通用的动画光标创作 Skill**，供未来制作任意主题、新增光标种类或重新制作现有主题时使用。

Skill 不应写死 Kamuri 的 45 种枚举、配色、目录结构或 Bevy 0.20 实现。它应能接收新的光标需求/语义、参考素材、尺寸与热点约束，指导创作方法的自主选择、素材生成、时序设计、技术与视觉质量验证、必要的迭代返工及最终交付。Kamuri 的特有流程可作为实例或可选参考资料。

按 Codex 当前支持的 Skill 规范提供可发现的 `SKILL.md` 及必要的脚本/参考资料。实际使用过且具通用价值的脚本应纳入并验证；临时草稿、无关素材和不可移植环境假设不应塞入 Skill。应实际尝试 Skill 的使用流程，确认后续有机会复用，而非仅生成一份流程介绍。
