# Table 连续区域选择、拖选与全选

Table 当前 `WidgetryTableSelection` 只有 `None`、单行、单列、单单元格，选择状态与焦点分离；本增量将其扩展为一个连续区域，同时保持原有 `WidgetryTableState`、`WidgetryTableEvent`、虚拟化身份和键盘焦点的语义。**一个 View 同时最多存在一块选区**，没有 Ctrl 追加离散选区的能力。

## 单元格、整行与整列三类选区

普通点击单元格创建单格选区，点击行号选择该行，点击列标题主体选择该列。Shift 点击只在与当前选择**同类型**时扩展：单元格形成以锚点和目标为对角的矩形，行号形成显示顺序中的连续行段，列标题形成连续列段。锚点保持初次普通点击确定的稳定 RowId/ColumnId；跨类型 Shift 点击按普通点击处理并重新设锚点，不生成行列混合选区。不同的 View 各自拥有独立选择及锚点。

例如在当前 View 按行 `R1 → R4 → R3 → R2`、列 `A → B → C` 显示时，以 `(R4,A)` 为锚点 Shift 点击 `(R2,C)`，选区是该 View 中连续的 `R4,R3,R2` × `A,B,C`，而不是按 Model 的索引取范围。即使 R3 的 Cell 尚未因虚拟化而实例化，也应被逻辑选中。

鼠标拖选只从**单元格**开始：初始按下一个单元格，移动超过合适阈值后持续更新矩形终点，并给予实时视觉反馈；结束时保留最后一块连续矩形选区。行号、列标题及列宽调整把输入留给各自的选择/Resize/列拖拽行为，不能把同一个按键会话解释成单元格框选。Cell 下的业务 Renderer、输入命中与捕获机制应保证起始稳定身份不在滚动复用后被替换成另一单元格。

## 整个当前 View 的全选

`Ctrl+A` 和点击 Table 左上角 Corner 都选中**当前 View 的全部投影行 × 当前全部列**，包括没有生成 UI Entity 的虚拟化单元格，**不包含已被当前 View 过滤掉的 RowId**。无 Ctrl+A 二次切换/取消全选；没有可供选择的有效数据行时保持空选择。只选表格实际数据，不把行号或列标题文本当作选区的一部分。

全选后的逻辑范围、复制操作和 UI 高亮必须使用当前完整投影，不以 `runtime.cells`、当前窗口的 `VisibleCells` 或屏幕像素集合代替。此处 Table 的全选与 ListView 默认 `Ctrl+A` 面向整个原始数据源的既有范围契约不同，不能混用。

## 稳定 ID、焦点与修复

范围端点记录稳定身份，导航与绘制根据最新 View 投影重新计算对应显示下标。新增/移除/过滤行或 Model 删除列后，应修复不再有效的选区，不能让过期 ID 参与渲染或复制；自动修复继续沿用项目“静默修复，不伪造用户选择事件”的约定。`focused_cell` 仍然是导航位置，不能直接等同于整个选区。

连续选择需要明确定义可查询的只读状态和程序化设置 API，避免把一个由锚点/终点表示的逻辑区域展开成完整的 Cell ID 集合；如此才能支持大表格的二维虚拟化。选区的各类用户变更通知延续“先写真实状态，再触发事件；同值不重复通知”的行为。

## Gallery、文档与完成条件

`gallery/src/pages/table.rs` 使用普通、共享双 View 和 `2000 × 40` 虚拟化表格展示单元格矩形拖选、Shift 连续单元格/行/列、跨类型 Shift 重新设锚点、Ctrl+A 与角落全选，以及屏幕外数据被逻辑选中。Gallery 状态展示应能看出选区种类与范围，而不只显示“选中一个 ID”；中英文说明改为当前 View 全选语义。

`crates/table/tests/interaction.rs`、`virtualization.rs`、`view.rs` 测试实际 Pointer 拖选、Shift 目标和锚点处理、横纵滚动跨离屏范围、多个共享 View 的不同显示顺序及选择隔离、Corner 点击、空投影、全选不含过滤行、数据删除/列删除自动修复、Disabled 与事件去重。保留原列宽 Resize、键盘 Focus、颜色选择高亮和 Row/Column Header 复用测试。同步 `docs/crates/table.md` 与 `tests/COVERAGE.md`。
