# 将基础控件文案归入各页面的 Key 类型

## 目标与范围

迁移 Button 页面及其中的 RadioGroup 演示、CheckBox、ComboBox、TextField、Tooltip、ScrollArea 的页面专属 Key。修改相应 Key 定义、中英文匹配和页面调用，不改变控件行为。

## 修改设计

沿用已经建立的公共语义分类，把只在某个页面表达特定行为的说明、状态和演示标签归入对应页面类型。RadioGroup 文案按实际页面职责组织，不因为它是独立 crate 就虚构新的 Gallery 导航页面。

普通、禁用、方向或通用操作等文案是否共享，以真实含义和跨页面使用为依据。已经归为 Common 或 Navigation 的 Key 直接复用；相似但含义不同的说明仍保留页面归属，不为了缩小枚举把它们合成泛化字符串。

每个迁移 Key 的定义、两种翻译、BSN 构造处、事件后的动态状态绑定和 Key 参数同时更新。保留原始文案和命名参数，不把 Rust 枚举替换成字符串索引，不增加运行时缺键兜底。尚未迁移的其他页面继续正常工作。

## 实施约束

涉及编译和运行的验证使用现有 Bevy 0.20、Windows 64 位 MSVC／DX12 环境，不以跨平台适配或绕过目标限制代替验证。

## 完成条件

完成这些页面的编译检查，并通过 BRP 检查新建页面、已经打开的页面和 Tooltip 动态内容在两种语言下的表现。语言切换不清空文本输入，不重新建立 ComboBox Model，不改变 Checked、三态值、选择、滚动和 Disabled。

覆盖页面离开后重新进入、展开颜色展示，以及已有动态状态文本的更新。已有国际化测试按实际影响调整；不机械要求为每个静态文案增加断言，也不重复建立一套 Gallery 测试系统。

## 预期产出

基础交互页面的文案具有清楚的类型归属，公共文案不重复，用户看到的内容与交互保持不变。
