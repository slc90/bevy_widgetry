# 建立 TextKey 的公共语义分层

## 目标与范围

调整 `gallery/src/i18n/key.rs`、`en_us.rs`、`zh_cn.rs` 及公共界面的使用点，建立 Common、Header、Navigation、ColorShowcase 等明确的公共语义类别。页面专属内容留给后续按页面迁移。

## 修改设计

保留强类型的顶层 TextKey，通过子枚举或等价的强类型结构表达归属，例如由顶层变体包裹公共类别。类别按语义和使用范围划分，不按中文或英文文本恰好相同就自动合并；真正跨页面复用的含义只保留一份定义，也不为追求页面自包含复制共享 Key。

同一批 Key 的类型定义、两种语言的穷尽匹配、公共 UI 调用和嵌套 Key 参数在这个增量内一并迁移。迁移期间允许顶层同时存在已分层类别与尚未迁移的页面变体，以保持编译完整；这是过渡状态，不增加长期别名、重复翻译表或无类型字符串回退。

LocalizedText、`tr`、`tr_args`、`with_key_arg` 和 BSN 文本绑定继续使用类型化 Key。保留已有 Reflect 等实际使用的能力，以及参数单次替换的语义：原始参数中出现花括号不能被当成新模板再次求值；缺失参数仍按现有方式保留占位并报告。

## 实施约束

涉及编译和运行的验证使用现有 Bevy 0.20、Windows 64 位 MSVC／DX12 环境，不以跨平台适配或绕过目标限制代替验证。

## 完成条件

公共导航、Header、主题颜色展示及真正的 Common 文案在中英文中逐项保持原内容。两种语言的匹配保持编译期穷尽，不用通配分支掩盖遗漏。

现有参数替换测试随类型变化更新，覆盖原始花括号值、缺失参数和 Key 参数。通过 BRP 验证语言切换原地更新公共文字，不重建页面，不重置 Theme、Scale Factor、输入或控件状态。这个增量不更改翻译措辞或引入新语言。

## 预期产出

可以逐步承接页面迁移的公共 Key 类型结构，以及已经完成迁移的公共界面文案。
