# 完成窗口与显示页面的 Key 分层

## 目标与范围

迁移 Window 页面及其 MessageBox、FileDialog 演示，以及 Waveform、Cursor 的专属 Key，完成顶层扁平页面变体的清理。范围包括相应动态标题、结果摘要、状态文本和两种语言匹配。

## 修改设计

按现有页面职责建立子类别，而不是为每一种内部部件建立独立翻译系统。文件选择操作、结果、过滤器标签与窗口标题保持明确归属；用户文件名、路径、波形业务数据和输入内容不转换成 Key。

迁移标题和结果中的 LocalizedText、Key 参数及格式模板，继续使用已经建立的 Window 语义标题入口。路径展示保留已经完成的结果路径修复中的前缀与摘要规则，不能在 Key 重组时恢复旧的标题文本猜测或路径改写行为。

完成后顶层 TextKey 只承担语义类别组合，不再保留用于迁移的扁平页面变体和重复别名。两种语言保持穷尽匹配，实际翻译内容、占位参数和切换语言的行为不变。按调用点检查遗漏，而不是用默认字符串或空字符串使编译和显示勉强通过。

## 实施约束

涉及编译和运行的验证使用现有 Bevy 0.20、Windows 64 位 MSVC／DX12 环境，不以跨平台适配或绕过目标限制代替验证。

## 完成条件

检查独立 Window、MessageBox、FileDialog 的创建与在场语言切换，以及 Waveform、Cursor 页面和公共导航的回归。正文同名文本、路径和可编辑内容不能误翻译；结果状态、窗口生命周期、正在运行的波形和 Cursor Theme 不因语言变化重置。

完成整套 Key 的定义与使用点核对，确认每个类别都有两种语言的编译期覆盖，过渡别名已移除。已有参数替换测试保持；BRP 对本次影响的动态文字与状态进行验证，不把这一步扩展为纯粹重复前序所有测试的阶段。

## 预期产出

完整的公共／页面分层 TextKey，以及不依赖字符串回退、没有迁移残留的中英文实现。
