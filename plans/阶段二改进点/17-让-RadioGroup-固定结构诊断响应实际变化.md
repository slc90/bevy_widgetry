# 让 RadioGroup 固定结构诊断响应实际变化

## 目标与范围

调整 `crates/radio_group/src/group.rs::initialize` 中已初始化 Group／Option 的结构诊断触发方式。保留新 Group 初始化与首项选择，不改动固定直接 Children 的外部契约。

## 现状与修改设计

当前初始化系统还在每帧遍历全部 Option，检查父级是否为 RadioGroup。正常静态 Group 的结构并没有变化，这段遍历主要承担重复诊断，不应长期放在热路径。

将检查绑定到新 Group／Option、相关父子关系变化和 Root／必要组件失效。需要考虑父级标记被移除而子项 ChildOf 本身没有变化的情况；不能只监听一个 Added 事件就宣布完成。BSN 尚未完成父子挂接时保留有界的构造期补偿，正常初始化完成后不再递归或全量检查固定结构。

校验仍必须在相应输入生效前维护正确前提。非法程序化请求继续由其执行路径验证，不依赖诊断缓存决定是否合法。使用现有 FailureState 区分首次持续故障、真正恢复和再次故障；每个新的非法 API 请求与同一结构故障的逐帧重复不是同一种日志场景。

本项不是新增动态 Option 重组能力。外部破坏固定结构仍按错误契约诊断，不为此建立第二套状态 Authority 或公开校验接口。

## 实施约束

涉及编译和运行的验证使用现有 Bevy 0.20、Windows 64 位 MSVC／DX12 环境，不以跨平台适配或绕过目标限制代替验证。

测量使用相同真实负载和既有 Benchmark 规范；内部工作量计数不成为公共 API。涉及可见行为时增加对应 Gallery 的 BRP 输入、ECS 状态与截图验证，原生 Window／Mouse 行为仍需 Windows 原生证据。

保留现有错误传播边界：真实失败以 BevyError 的 Error 级别交给宿主，必要的中文诊断在能说明原因的位置记录；不靠主动 panic、吞掉错误或替换宿主 Handler 维持流程。

## 完成条件

回归覆盖完整 BSN 构造、延后挂接、非法直接父级、父级标记移除、Root 回收及有效恢复。初始化的首项选择和合法程序设置的静默语义保持不变；持续故障日志不逐帧刷屏，真实失败仍按 Error 契约传播。

用测试内计数或定向 Benchmark 区分“没有重复结构校验”和“没有产生输出写入”。静止、单个 Group 变化和多个 Group 并存时分别检查工作范围；没有测量前不承诺耗时收益，也不向公共 API 增加调试计数器。

## 预期产出

按生命周期和相关结构变化触发的 RadioGroup 诊断，消除已初始化固定结构的永久全量检查。
