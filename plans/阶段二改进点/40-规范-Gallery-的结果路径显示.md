# 规范 Gallery 的结果路径显示

## 目标与范围

修改 `gallery/src/pages/window/file_dialog.rs` 的结果摘要，使 Windows 扩展长度路径在展示时使用易读形式。改动只作用于显示文本，不修改 FileDialog 的结果类型、PathBuf、真实文件访问路径或长路径支持。

## 修改设计

当前 `bounded_path` 直接对 `to_string_lossy()` 的结果截断，因此会显示 `\\?\C:\...`。按 Windows 路径前缀类型生成展示字符串：VerbatimDisk 显示普通盘符路径；VerbatimUNC 显示 `\\server\share\...`。普通路径保持原样；不能简单全局删除字符，也不能把未知的 Volume、Device 或其他前缀猜成普通磁盘路径。

库内已有基于 `Path::components` 与 `Prefix` 的显示逻辑，可参考其语义，在 Gallery 的显示职责内使用相同规则。不为这一个调用暴露 FileDialog 私有样式模块，也不新增通用路径改写层。展示结果是单向派生文本，不能反向构造实际选择或访问的路径。

规范化发生在摘要截断之前。保留每条最多 240 个字符、最多列出前 8 条路径、超出时加省略标记的行为；字符截断不能变成按 UTF-8 字节截断。多选数量仍使用完整结果数量，Cancelled、Session 路由、页面 Owner 和本地化参数处理不变。

## 实施约束

涉及编译和运行的验证使用现有 Bevy 0.20、Windows 64 位 MSVC／DX12 环境，不以跨平台适配或绕过目标限制代替验证。

## 完成条件

覆盖普通盘符、扩展盘符、普通 UNC、扩展 UNC、未知前缀、相对路径、中文名称及超长名称。验证显示前缀正确、截断和数量正确，原始 Result 中的每个 PathBuf 均未变化。

通过 Gallery 的单选、多选和保存结果检查真实展示，并检查切换语言后路径原文不被翻译。已有相关测试随修改更新；Gallery 不因这一显示修改强制建立新的测试框架。库文档中仍然成立的长路径说明保留，Gallery 文档的已知显示问题在实际修复后移除。

## 预期产出

一个仅规范阅读文本、保留原始路径语义与摘要限制的 Gallery 结果视图。
