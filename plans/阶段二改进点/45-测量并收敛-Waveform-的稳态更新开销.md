# 测量并收敛 Waveform 的稳态更新开销

## 目标与范围

围绕 `crates/waveform/src/runtime.rs::update_waveforms` 与 `WaveformRuntime::update`，补足能够评价稳态调用成本的 Benchmark；只有收益得到证明时才合入提前跳过更新的生产改动。这是低优先级候选，不把已有 NoOp 判断描述成已证实的性能瓶颈。

## 修改设计

现有 Runtime 在相同采样边界、相同输出密度时已经避免读取和压缩数据。优化对象是此前仍发生的 System 遍历与重复检查。沿用 `crates/waveform/benches/update.rs`，必要时补充实际 ECS 更新入口的稳态测量，区分 Runtime 内部成本和外层扫描成本；只测一个从来没调用 System 的函数，不能证明消除了 System 开销。

评估快路径时，以最近成功提交的状态为依据，不能把最近一次尝试当成成功。Source 读取失败后，即使 Cursor 和输出密度没有变化，也必须允许原有重试；失败结果不能写入“已处理”缓存，使后续永远跳过读取。数据提交、失败日志与恢复诊断保留原有边界。

`WaveformUpdateStats` 是可观察契约。成功更新之后的稳定帧仍应表达本次 NoOp、零读取和对应的 Reduction 状态，不能一直保留上一次 FullRead／IncrementalRead 或宽度重建的统计。输出密度变化仍需重新生成表示；Revision 只在原有应改变的情形改变。隐藏、零宽和再次可见的处理也不能被快路径短路。

## 实施约束

涉及编译和运行的验证使用现有 Bevy 0.20、Windows 64 位 MSVC／DX12 环境，不以跨平台适配或绕过目标限制代替验证。

保留现有错误传播边界：真实失败以 BevyError 的 Error 级别交给宿主，必要的中文诊断在能说明原因的位置记录；不靠主动 panic、吞掉错误或替换宿主 Handler 维持流程。

## 完成条件

测量包含稳态、跨采样边界、连续前进、回退／跳转、输出密度变化及多实例负载，记录优化前后同场景的实际工作量和耗时。使用既有测量规范和足够样本，不只挑最快值，不通过降低数据处理量取得表面收益。

回归覆盖同值输入下 Source 先失败后恢复、Stats 从有效更新切换到 NoOp、宽度改变后的 Reduction、零宽到可见，以及有效输出在失败时保持不变。Ring Buffer、Reducer、离屏渲染和 GPU 资源清理不在修改范围，不能为快路径另建一套渲染或数据接口。

收益不足、噪声无法区分或行为无法保持时，保留当前生产实现，交付可复用的测量场景与结论；不能把“尝试过”写成“已优化”。普通正确性测试不加入依赖机器快慢的硬耗时断言。

## 预期产出

能判断稳态成本的针对性 Benchmark，以及证据支持时的最小快路径改动；读取重试、Stats 与现有可见输出语义不变。
