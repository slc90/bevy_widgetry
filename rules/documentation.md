# 注释与文档规则

## 语言

代码和配置文件中的注释，包括 Rustdoc，统一使用英文。

Git Commit Message 使用英文，具体要求遵循 `rules/git.md`。

普通 Markdown 文档不强制使用特定语言，可根据内容和阅读对象选择中文或英文。

日志正文继续使用中文，具体要求遵循 `rules/logging.md`。

技术术语、API 名称和代码标识符应保持准确，不为了语言统一而翻译或改写。

## 注释内容

代码注释仅用于记录无法从代码本身直接理解的重要坑点，包括：

- 触发问题的条件。
- 不采用当前写法会产生的错误或意外行为。
- 当前实现规避问题的原因及必要约束。

注释应解释不明显的原因和限制，而不是复述代码操作。

不为普通 Type、Field、Function、Module 或 Test 编写显而易见的职责说明，也不在 `lib.rs`、`main.rs` 或 Integration Test 文件头部重复描述已集中维护的功能与测试覆盖信息。

Crate 功能及行为契约由 `docs/crates/` 集中记录，Gallery 功能由 `docs/gallery.md` 记录。

Integration Test 的 Coverage Model 由对应 Crate 的 `tests/COVERAGE.md` 维护，具体遵循 `rules/testing.md`。

## 注释格式

所有代码和配置注释必须单独成行，不得写在代码行末尾。

注释应按语义分句。多个独立句子分别占用注释行，不使用分号将多个句子挤在同一行。

注释应紧邻相关代码，并在修改代码时同步检查其准确性。问题或特殊约束已经消失时，应删除不再适用的注释。

## 特殊例外

根目录 `Cargo.toml` 中保留 BRP MCP 安装命令及其配套说明注释，作为普通注释限制的明确例外。

具体安装命令、版本和参数以 `Cargo.toml` 中的内容为准，不在规则文件中重复维护。
