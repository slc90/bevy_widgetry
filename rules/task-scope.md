# 任务范围规则

## Narrow 到给定目标

Codex 必须围绕当前明确给定的目标工作。

只修改完成当前目标所必需的代码和文件。每个 diff 都应能够直接回答：

> 这个修改为什么是完成当前目标所必需的？

如果无法回答，就不应包含在当前任务中。

## 禁止顺手修改

禁止 opportunistic cleanup，包括但不限于：

- 与目标无关的重构。
- 与目标无关的 bug 修复。
- 顺手改名。
- 顺手移动文件。
- 顺手重排模块或目录。
- 顺手抽 helper。
- 顺手调整公共 API。
- 仅因为“更统一”“更现代”“更优雅”而扩大 diff。

发现与当前目标无关的问题时，可以在结果中指出，但不要修改。

## 必要修改自主执行

如果某项修改是正确完成当前目标所必需的，则 Codex 可以直接自主完成，不需要逐项请求确认。

这包括：

- 必要的局部重构。
- 阻塞当前目标的已有 bug 修复。
- 必要的跨 crate 修改。
- 为当前目标所必需的接口调整。
- 为满足项目硬规则所必需的配套修改。

判断标准：

```text
不做这个修改
    ↓
当前目标无法完整、正确地完成
    ↓
允许直接修改
```

反之：

```text
不做这个修改
    ↓
当前目标仍可完整、正确地完成
    ↓
不要修改
```

## 不保留猜测性代码

不得因为“以后可能会用”而保留当前无明确职责的代码、接口或 dead code。

未来需求出现后再根据真实需求实现，不用当前代码为未知未来预留没有依据的实现。
